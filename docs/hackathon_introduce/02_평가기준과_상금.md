| 결선 | 트랙별 상위 5개, 총 10개 프로젝트 | 최종 심사위원이 데모 영상을 실시간 시청하고 동일 평가표로 최종 순위 결정 |

폐막·결선은 **11월 10일(화) 02:00 KST**다. 가이드는 영상 실시간 시청을 명시한다. 별도 발표자의 필수 참석 방식·발표 길이·질의응답 규칙은 현재 문서에서 확인되지 않았다.

## 공식 배점과 팀이 보여줄 증거

| 평가 항목 | 비중 | 공식 평가 질문 | 준비하면 좋은 증거 — 권장 |
| --- | --- | --- | --- |
| Impact — 실제 영향력 | **30%** | 현실 잠재력은? 누가 얼마나 큰 혜택을 받는가? 사람들이 사용할 제품인가? 문제 정의에 부합하는가? | 구체적 사용자·기존 작업의 어려움·개선 전후 비교·검증 가능한 사용 사례 |
| Use of Meta AI Tooling — Meta AI 도구 활용 | **25%** | 얼마나 창의적으로 썼는가? 기본 연동을 넘어섰는가? 예상 밖의 능력을 보여주는가? | 실제 사용 모델·핵심 기능에서의 역할·해당 모델로 가능한 차별점·실제 실행 장면 |
| Technical Depth & Execution — 기술적 깊이와 완성도 | **20%** | 설계·구현이 탄탄하고 세심한가? 깊이 고민하고 정성 들인 결과물인가? | 설계 선택의 이유·입력부터 결과까지 동작·오류 처리·핵심 시나리오 검증 |
| Demo — 데모 | **25%** | 실제 작동하고 인상적인가? 라이브 환경에서도 유지되는가? 영상의 완성도·흥미는? | 3분 영상·작동 제품·안정적인 시연·결과가 명확하게 보이는 화면 |

두 트랙에 각각 다른 배점은 공개되어 있지 않다. 메인 공지의 트랙별 소개 문구보다 위 정량 평가표가 구체적인 평가 기준이다.

가중 합산을 이해하기 위한 계산식: `총점(10점 기준) = Impact×0.30 + Meta 활용×0.25 + 기술×0.20 + Demo×0.25`. 이는 공개 가중치의 단순 산식이며, 세부 동점 처리·내부 점수 보정 방식은 공개되지 않았다.

**실행 제안:** 기능 수를 늘리는 것보다 한 사용자의 중요한 문제를 Meta 모델로 끝까지 해결하는 작동 흐름을 우선한다. 가짜 지표나 검증되지 않은 성과를 결과처럼 제시하지 않는다.

## 보너스상 — 가이드에 공지된 합계 $50,000

| 상 | 금액 | 대상·조건 | 선정 방식 |
| --- | ---: | --- | --- |
| Most Viral Project | $20,000 | 프로젝트 데모를 X에 게시하고 해커톤 플랫폼에 게시물 링크 제출 | 11월 8일 EOD까지 좋아요·재게시·댓글 총참여도. EOD의 시간대는 미명시 |
| Best Build on Meta Open Weight Models | $10,000 | Muse Glimmer 또는 Muse Spark Open을 자체 하드웨어나 파트너 추론 인프라에서 실행 | 1차 심사 때 표시, 인프라 파트너가 적격 모델 실행 검증 |
| Community Vote | $10,000 | 공개 프로젝트 갤러리 최다 득표 | 인증 계정당 1표, 플랫폼 총투표 수. 11월 16일 Discord 발표, 시각 미정 |
| Best Agentic Use-Case | $5,000 | 의미 있는 작업 완료·의사결정·여러 단계 워크플로 조율에 에이전트를 효과적으로 사용 | 자율성·작업 완료 효과성·실용성 |
| Best Creative Build | $5,000 | Muse Image 또는 Muse Wonder 기반의 독창적이고 매력적인 창작 프로젝트 | 1차 심사 때 표시 후 독창성·완성도·최종 경험에서 모델 활용 효과 평가 |

보너스상을 위해 필수 제출 범위를 무리하게 늘리지 않는 것이 좋다. 복수 보너스 동시 수상이나 본상과의 중복 수상 허용 여부는 확인되지 않았다.

**규정과 가이드의 차이:** 공식 규정은 보너스 총액을 최대 $50,000, 개별 상 종류·금액·배분을 주최 측 재량으로 정할 수 있다고 적고, 추가상 발표를 11월 10일 전후로 설명한다. 상세 가이드는 위 5개 상과 커뮤니티상 11월 16일 발표를 구체적으로 적는다. 현재 운영 계획은 가이드 기준으로 참고하되, 최종 공지를 다시 확인한다.

## 우리 팀의 사전 점검 — 권장

- [ ] 혜택을 받는 사용자와 문제를 한 문장으로 설명한다.
- [ ] 두 문제 정의 중 하나에 어떻게 부합하는지 설명한다.
- [ ] Meta 모델이 핵심 기능에 기여하는 부분을 실제 동작으로 보여준다.
- [ ] 기간 중 새로 개발한 기능·코드·작동 방식을 명시한다.
- [ ] 대표 시나리오를 처음부터 끝까지 반복 실행한다.
- [ ] 3분 영상·저장소·제품의 내용이 서로 일치한다.
- [ ] 도전할 보너스상의 추가 조건을 별도로 충족한다.
