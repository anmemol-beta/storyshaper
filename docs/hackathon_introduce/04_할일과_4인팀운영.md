## 지금 내가 할 일 — 우선순위순

### 1. 팀의 출전 조건과 방향 확정

- [ ] 4명 각자가 승인받았는지 확인한다. 한 사람의 승인·Discord 입장으로 전원 승인을 가정하지 않는다.
- [ ] 전원이 나이·소속·지역 등 참가 자격과 [공식 규정](08_공식규정_권리와_상금지급.md)을 확인한다.
- [ ] **대표자 1명**을 정하고 전원이 팀을 대신한 제출 권한을 부여한다.
- [ ] Indie Developer 또는 Startup 중 한 트랙만 정한다. **일반 4인 팀도 Indie 참가 가능.** Startup이면 대표자의 현직 직원·권한 요건을 확인한다.
- [ ] 두 문제 정의 중 하나를 정하고, “누구의 어떤 문제를 어떤 Meta 모델 기능으로 해결하는가”를 한 문장으로 적는다.
- [ ] [피해야 할 프로젝트 목록](01_대회개요와_참가규칙.md)을 대조한다.
- [ ] 팀원 이름·플랫폼 프로필·GitHub 계정·담당 범위를 팀 내부에서 확정한다.

### 2. 개발 접근권한과 비용 준비

- [ ] **각자** [Meta $150 신청서](https://docs.google.com/forms/d/e/1FAIpQLScam78z7tHsNYibiFyJQVFzEgr0coyBTiY568SxxNbsPa3jiw/viewform)를 제출한다. 대리 신청 불가.
- [ ] 각자 Billing에서 크레딧 반영을 확인한다. 순차 지급이므로 신청 완료와 지급 완료를 나눈다.
- [ ] 신용카드 등록·임시 승인·이용 조건을 본인이 확인하고 필요한 절차를 진행한다.
- [ ] Billing의 Spend Limit **알림**을 설정하고 실제 사용량을 점검한다. 공지는 자동 과금 차단을 보장하지 않는다.
- [ ] 선택한 Meta 모델로 최소 한 번 실제 호출·응답을 확인한다.
- [ ] 필요하면 Baseten·Modal·Fireworks 지원을 신청한다. 조건과 개인/팀 단위가 다르다.
- [ ] 공유 저장소와 개발 환경을 준비하고 키·비밀정보가 코드·영상에 포함되지 않게 관리한다.
- [ ] 개막식에서 신규 개발 인정 시작 시각과 규칙 변경을 확인한 뒤 구현한다.

### 3. 평가 기준에 맞춰 개발

- [ ] 핵심 사용자 흐름 1개를 정해 입력부터 결과까지 실제 동작하게 만든다.
- [ ] Meta 모델의 핵심 기여와 단순 연동을 넘어선 차별점을 설명한다.
- [ ] 검증 가능한 개선 효과를 기록한다. 아직 측정하지 않은 효과는 가설로 표시한다.
- [ ] 실패·지연·예외 입력을 확인하고 데모 경로를 안정화한다.
- [ ] 커밋·작업 기록으로 행사 중 새로 개발한 부분을 식별할 수 있게 남긴다.
- [ ] 매일 또는 필요 시 `#announcements`와 메인 공지를 확인한다.
- [ ] 질의응답 전 재현 단계·정확한 오류·사용 모델을 정리한다. 공유 시 비밀정보는 제외한다.

### 4. 제출과 후속 일정

- [ ] 대표가 [제출 링크](https://cerebralvalley.ai/e/meta-ai-developer-hackathon/hackathon/submit)의 개방 상태·필드를 미리 확인한다.
- [ ] 공개 코드 저장소, 3분 영상, 실제 제품 접근 경로를 정리한다.
- [ ] 신규 개발분과 사용 모델·작동 방식을 제출 내용과 영상에서 일치시킨다.
- [ ] **팀원 4명 전원**을 제출 페이지에 기재한다.
- [ ] 시크릿 창 등으로 저장소·영상·제품 링크가 열리는지 확인한다.
- [ ] 한국 **11/04 22:00 내부 목표**로 제출한다. 공식 마감은 **11/05 11:00 KST**다.
- [ ] 실제 제출 완료 화면·접수 기록을 보관한다.
- [ ] 11/10 02:00 KST 결선 공지와 필요한 참석 안내를 확인한다.
- [ ] 보너스상 참여 시 별도 게시물 링크·모델 검증·투표 조건을 확인한다.

## 4인 역할 분담 초안 — 팀 합의 필요

| 역할 | 주된 책임 | 완료 기준 |
| --- | --- | --- |
| A: 대표·기획·제출 총괄 | 문제·트랙·범위 확정, 규정·일정 점검, 팀원 명단·제출·접수 증빙 | 팀원 전원 확인 후 프로젝트 1건 접수 완료 |
| B: Meta 모델·백엔드 | 모델 호출·데이터 흐름·에이전트 동작·실패 처리·사용량 | 핵심 시나리오 실제 실행 및 모델 기여 증명 |
| C: 화면·통합·제품 경험 | 사용자 입력·결과 화면·사용 흐름·배포·접근성 | 심사위원이 제품을 열고 핵심 흐름 확인 가능 |
| D: 검증·데모·문서 | 사용자 효과 검증·시나리오 점검·3분 영상·README·신규 작업 증빙 | 제출 자료와 실제 동작 일치, 링크 접근 점검 완료 |

사용자의 이름·기술·담당 업무 정보가 없어 A~D를 실제 사람에게 배정하지 않았다. 전원이 개발에 기여하고, 위 책임은 중복·조정할 수 있다. 대표자와 A 역할 담당자가 같을 필요는 없지만 대표 권한은 명확해야 한다.

## 팀이 미리 합의할 사항 — 권장

- 대표의 제출·통지 수령 권한과 부재 시 대처.
- 기능 범위·작업 담당·통합 방식·내부 마감.
- 기존 코드·새 코드의 구분, 코드·데이터·자산의 사용권과 공개 범위.
- 영상·프로젝트 설명·대외 게시물 확인 절차.
- 수상 시 상금 배분 방식과 대표 일괄 수령/분할 지급 선택. **4명 균등 분배를 자동 가정하지 않는다.** 공식 규정은 팀이 서면으로 지급 배분을 알리도록 한다.
