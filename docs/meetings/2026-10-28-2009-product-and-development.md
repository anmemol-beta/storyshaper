## 핵심 합의

1. 기능별로 병렬 개발하고, 중간에 합쳐 실행·검증한 뒤 서로 맞지 않는 부분을 조정하는 방식으로 진행한다.
2. 제품의 핵심 가치는 **동화의 교훈을 유지하면서 아이의 창의성을 이끌어내는 경험**과 **익숙한 부모 목소리의 낭독**이다. 부모 목소리를 단순한 후속 확장으로만 표현하지 않는다.
3. 현준님은 목소리 복제와 캐릭터별 음성 기능을 맡는다. 나머지 개발 담당은 이 회의에서 최종 확정되지 않았으며 [2차 회의](2026-10-28-2049-roles-and-integration.md)와 사용자 확인으로 확정됐다.
4. 이야기의 주요 사건·교훈·결말은 고정한다. 아이의 답은 그 결과로 이어지는 과정의 허용 범위 안에서 반영한다.
5. 기존 동화를 등장인물·장면·질문으로 자동 분해하는 에이전트는 후순위(TBD)로 둔다. 먼저 사람이 정의한 장면과 배역 데이터를 사용해 실시간 동화 진행 에이전트를 만든다.

## 논의 내용

### 개발·데모 준비 방식

- 20:14~20:17: 기능별 개발 → 중간 통합 테스트 → 조정 → 반복하는 협업 방식을 공유했다.
- 주말인 **10/31~11/1 무렵까지 시연할 기능을 안정화**하고 **11/2(월)부터 영상 콘티·촬영**을 진행하는 목표를 논의했다. 실제 완료나 고정된 납기 보장은 아니다.
- 콘티·촬영 담당자로 언급된 이름이 자동 전사에서 다르게 기록돼 정확한 이름은 확인이 필요하다.
- 후속 회의에서는 주말까지 기다리지 않고 금요일에 먼저 통합하기로 했다.

### 부모 목소리와 캐릭터 음성

- 20:19~20:25, 20:40~20:46: 부모 목소리로 읽어주는 친밀감과 정서적 의미를 제품·데모에서 강조하자는 의견을 나눴다.
- 직접 녹음 외에 이미 보유한 음성·영상에서 참조 음성을 가져오는 방법을 제안했다. 해당 입력 방식과 이용 조건은 추가 검토할 항목이며 이번 회의에서 구현 완료를 확인하지 않았다.
- 한 목소리로 모든 배역을 읽는 방식과 배역별 음성을 구분하는 방식을 비교했다. 내레이터·등장인물의 성격에 맞는 음성 배정과 표현을 구체화하기로 했다.
- 등장인물과 성격·화자 메타데이터를 먼저 지정하면 음성 개발이 해당 정보를 받아 구현할 수 있다.

### 질문 설계와 동화 에이전트

- 20:26~20:39, 20:46~20:48: 단순한 빈칸 채우기보다 아이가 재료·행동·결과의 인과관계를 생각하게 하는 질문을 지향한다.
- 아이의 답을 모두 그대로 생성하는 대신, 이야기의 교훈과 정해진 결과에 맞는지 판단하고 재질문·안전한 방향으로 유도해야 한다.
- 두 종류의 에이전트를 구분했다.

| 구분 | 역할 | 우선순위 |
| --- | --- | --- |
| 동화 분석·구성 | 원문에서 등장인물·장면·질문·고정 결과 추출 | 후순위, 초기에는 사람이 설정 |
| 실시간 동화 진행 | 아이 입력의 적합성 판단, 허용 변경·대사 생성, 다음 이야기로 연결 | 우선 개발 |

- 질문과 판단 기준에는 문학·교육 관련 연구를 참고하자는 의견이 나왔다. 관련 연구 조사는 아직 수행되지 않았으며 구체적인 교육 효과도 검증되지 않았다.

### 이미지에서 짧은 영상으로 확장

- 20:26 무렵: 늑대가 바람을 불거나 집이 날아가는 동작을 짧은 영상으로 보여주는 방안을 논의했다.
- 10초 이내 장면이 예시로 언급됐다. 기존 로드맵의 2~5초 후보와 함께 검증할 범위이며, 최종 길이·모델·비용·지연 시간은 미정이다.
- 아이가 고른 재료와 결과의 인과관계가 영상에서도 유지돼야 한다. 기능 채택과 담당은 2차 회의에서 구체화됐다.
