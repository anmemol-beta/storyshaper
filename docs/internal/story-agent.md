2026-10-28 작성, 2026-10-30 선택적 독립 검토·속도 최적화와 단계 2의 이미지·마이크 연결 범위 갱신. 대상 연령은 사용자 확인 기준 4~7세다. 낯선 재료 해석과 짧고 쉬운 과정 설명·질문, 새 답마다 실시간 그림 생성을 시험한다. 연령별 세부 기준·페르소나·교육 효과와 폭넓은 성능 최적화는 후속 작업이며, 현재 결과의 아동 이해도·자연스러움 검증을 완료한 것은 아니다.

## 10/31 아이용 독서 화면·그림 대기·키워드 전용 입력

- **후속 사용자 변경 — 수동 이동 우선:** 그림 안의 ◀·▶는 아래의 그림 잠금과 별개로 언제나 이동한다(첫 장면·결말 경계 제외). 클라이언트 요청·녹음·카메라·낭독·이미지 폴링을 취소하고 늦은 콜백을 무시한다. 그림 대기 중 ▶는 승인된 다음 본문을 바로 열며, 그림을 건너뛰었다는 안내를 표시한다. 최신 질문의 ▶는 `POST /api/advance`에 `sessionId`·`version`·`requestId`를 보내 서버 기본 선택으로 한 단계 진행한다. 모델 호출·새 이미지 작업 없이 진행하며 중복 ID는 재사용한다. 서버가 먼저 진행한 경우 현재 장면만 돌려주고, 진행 중 이야기 요청은 교체된 세션에 커밋할 수 없다. 기존 일반 답변의 그림 잠금은 유지한다. 재시도 불가 상태도 ▶로 계속 읽을 수 있다. 외부 제공자에게 이미 전송한 호출 자체의 즉시 철회는 보장하지 않지만 해당 결과의 화면·진행 적용은 차단한다.

- 다음 수동 확인: 오프라인 시작 → 글로 모호한 답 → 세 키워드 확인 → 한 번 터치 → 새 그림과 다음 질문 확인. AI에서는 정상 음성·첫 실패·그림 대기 중 연속 탭·생성 실패·생성 중 재시작을 시험한다. 실제 iPad·Muse 생성 품질/지연·권한 팝업은 별도 실기기 확인 대상이다.

## 10/31 중복 실행과 포트 충돌

- 사용자가 직접 실행하기 전에는 에이전트가 띄운 시험 서버를 종료한다. 이번 `Address already in use`는 이전 확인용 `src.server` 프로세스가 8000을 점유한 것이 원인이었고 해당 프로세스를 종료했다.
- 동일 포트 중복 실행은 traceback 대신 사용 중인 포트·기존 앱 주소·기존 터미널에서 Ctrl+C 후 `python3 -m src.server` 재실행 안내를 출력하고 종료 코드 1을 반환한다. 다른 종류의 시작 오류는 숨기지 않는다.
- 실제 CLI를 임시 점유 포트에서 실행한 회귀 검사가 수정 전 같은 traceback으로 실패하고 수정 뒤 통과했다. 실제 모델을 호출하거나 다른 프로세스를 자동 종료하지 않는다.

## 10/31 공식 실행 진입점

- 공식 실행 명령은 `python3 -m src.server`다. `src/server.py`에서 기존 전체 통합 서버를 호출하며 기본 8000, `.env`, 속도 최적화, 그림·음성·카메라 경로를 그대로 사용한다. README·데모 스크립트·기능별 실행 안내를 통일했다.

### 선택적 독립 검토와 속도 최적화 — 2026-10-30

통합 앱(`src.server`)의 기본은 `adaptive`, 초안과 필요한 독립 검토의 추론은 모두 `low`다. 키가 설정된 기존 `.env`는 그대로 사용할 수 있다. 서버를 재시작하고 새 세션을 시작해야 새 경로가 적용된다. `StoryEngine`을 직접 생성하는 기존 도구는 호환성을 위해 `two_call` 기본값을 유지하며, 새 벤치마크·smoke·앱은 파이프라인을 명시한다.

| 입력·대사 조건 | 모델 요청 | 진단 |
| --- | ---: | --- |
| 등록 재료의 단순 선택, 서버 검사와 관찰 과정→결과 검사를 통과한 예상 응답 | 1 | `phase:local_validation`, `independentReview:false` |
| 새 재료와 그 후속 턴 | 2 | `reviewReason:custom_material` |
| 부정·여러 조건·긴 답·등록 재료에 추가한 미검증 수식 | 2 | `complex_answer` 또는 `ambiguous_material` |
| 다른 재료 언급·예상 전 결과 노출·관찰 과정 확인이 어려움 | 2 | `material_conflict`, `premature_outcome`, `process_quality` |
| 집 이동·결말 | 2 | `story_transition` |
| 터치 선택·일부 로컬 차단 | 0 | 준비된 기존 경로 |

위 수는 정상 처리 기준이다. 제공자 오류·깨진 JSON·서버 검사 실패는 실제 시도한 호출만 기록하고, 자동 재시도나 검토 실패 우회를 하지 않는다. 모델이 돌려준 안전 판정만으로 검토 생략 여부를 정하지 않는다. 과정 어휘 검사는 빠른 경로를 고르는 보수적인 신호이며, 표현이 다르면 거절하는 대신 독립 검토를 받는다. 일반 생성 대사의 의미 품질 전체를 증명하는 검사는 아니므로 기존 전부 검토 방식과 같은 안전성이 입증됐다고 해석하지 않는다.

재료 선택의 중복 문맥을 공유하고 아이 답을 문맥 뒤에 둔다. Spark에는 Responses의 `text.format` JSON Schema를 지정하고, 상태·ID·선택지·의미 검사는 계속 서버가 수행한다. [`story_agent/output_schema.py`](../../story_agent/output_schema.py)는 출력 형태만 제한한다. 새 그림은 `reasoning_strength:low`로 요청하되 독립 이미지 검수는 유지한다. 텍스트의 1호출과 그림·전사·낭독을 포함한 전체 호출 수는 다르다.

비교할 때는 같은 언어·같은 답으로 새 세션을 시작하고 **진단 정보 보기**의 `performance.totalMs`, `modelCalls`, `calls`, `pipeline`과 `independentReview`, `reviewReason`을 확인한다. 맞장구와 그림 대기 시간은 텍스트 생성 시간과 분리해서 본다.

```bash
# 기본 최적화 + 기존 마이크·카메라·실시간 그림
python3 -m src.server

# 비교하려면 실행 중인 서버를 종료하고 같은 8000에서 다시 시작
STORY_AGENT_PIPELINE=two_call python3 -m src.server

# 유료 호출 없는 고정 문답 비교
python3 -m story_agent.benchmark --mock --pipeline adaptive
python3 -m story_agent.benchmark --mock --pipeline two_call
```

`.env.example`에 설정을 기록했다. `STORY_AGENT_PIPELINE=two_call`로 항상 검토, `STORY_AGENT_REVIEW_EFFORT=default`로 예전 기본 추론, `STORY_AGENT_STRUCTURED_OUTPUT=0`으로 제공자 스키마 강제만 끄고 서버 검사를 유지할 수 있다. `STORY_IMAGE_REASONING_STRENGTH=high`는 그림 정제를 이전 기본 방식으로 비교할 때 사용한다. 환경변수 변경 후에는 서버를 재시작해야 하며, 외부에 설정한 환경변수가 `.env`보다 우선한다.

자동 확인: 한영 등록 재료의 9턴은 **18→12호출**, 비닐 선택·아이스크림 선택·잘못된 예상의 고정 비교는 **6→4호출**이며 모두 수용됐다. 한국어 아이스크림 선택의 첫 입력 문맥은 **5,558→2,937자(약 47% 감소)**다. 이들은 모형 응답과 요청 직렬화의 측정이며 토큰 수·실제 지연 개선률이 아니다. 원문 없는 기록은 [`benchmarks/2026-10-30-adaptive/`](benchmarks/2026-10-30-adaptive/)에 둔다. 실제 Muse의 새 경로·스키마 결합·자연스러움과 그림 저추론 품질은 이번에 실호출하지 않았으며 사용자 시험이 필요하다.

초기 구현 검증은 키 없이 진행했다. 이후 2026-10-28 사용자에게 발급받은 키를 `.env`에 저장하고 실제 Muse Spark 한국어 생성·검증과 9턴 완주를 확인했다. 키는 Git에서 제외하고 파일 권한을 `0600`으로 설정했다. 키 설정 여부만으로 성공을 판단하지 않으며, 준비된 대체 대사와 실제 생성 결과를 구분한다. 전체 분기의 모델 품질·지연 평가는 별도로 필요하다.

버전을 바꾸면 해당 방식으로 새 세션을 시작한다. 키를 새로 설정했다면 서버를 재시작하고 화면을 새로고침한다. 현재 `index.html`에서 실제 자유 입력·마이크·카메라·그림을 함께 사용한다. `agent.html`은 직접 주소로만 여는 개발용 화면이다.

## 영어·한국어 전환

상단 **English / 한국어** 버튼으로 안내·현재 대사·질문·선택지를 바꾼다. 언어 설정은 브라우저에 저장되어 기존 그림책과 시험 화면에서 함께 사용한다. 현재 집 재료·사건·질문 단계·재시도 횟수는 유지된다. 언어 전환은 모델을 호출하지 않으며, 이미 생성된 현재 대사는 같은 장면의 검증된 번역 대사로 표시한다. 이후 새 답변은 선택한 언어로 모델에 요청한다.

이전 시험 기록과 사용자가 직접 입력한 답변은 비교·추적을 위해 당시 언어를 유지한다. 상태 검사기의 `sceneId`·`material` 같은 식별자도 언어에 관계없이 동일하다. 기존 그림책의 한국어 낭독은 브라우저 음성이며, 영어 MP3나 부모 목소리 복제를 한국어 낭독으로 표시하지 않는다.

## 질문은 어디까지 바뀌나

사람이 질문의 목적·시점·허용 답변과 사건 분기를 작성한다. 모델은 현재 상태와 확정된 분기에 맞춰 짧은 다음 내용과 질문을 작성한다. 첫 시험에서는 각 집에 재료 선택·결과 예상·이유 설명의 세 참여 지점을 둔다.

| 집의 재료 | 확정할 사건 | 그 사건을 반영하는 질문 예 |
| --- | --- | --- |
| 종이·짚 | 늑대의 바람에 흩어짐 | 바람이 불자 왜 집이 흩어졌을까? |
| 나무 | 느슨하게 쌓은 나무가 무너짐 | 나무가 무너지지 않게 하려면 무엇이 필요할까? |
| 과자 | 늑대가 과자 벽을 먹음 | 늑대가 벽을 먹자 집은 어떻게 되었니? |
| 아이스크림 | 따뜻한 햇볕에 녹음 | 무엇 때문에 집이 녹았을까? |
| 마지막 집의 벽돌·돌 | 튼튼한 집에 함께 안전하게 머묾 | 이번 집은 왜 바람에도 버틸 수 있었을까? |

표의 질문은 개념 예시다. 실제 반환 질문의 목적과 허용 답변은 메타데이터와 현재 장면을 따른다. 예상 질문에서는 아이의 다른 예측도 수용할 수 있고, 이후 실제 사건을 설명한다. 이전 사건이나 이미 정한 재료를 모델이 소급해 바꾸게 하지 않는다.

첫 두 집에서 벽돌·돌처럼 튼튼한 재료는 필수 사건과 충돌하므로 그 뜻을 인정한 뒤 다른 허용 재료를 안내한다. 마지막 집의 약한 재료도 같은 방식으로 다시 안내한다. 10/29 사용자 결정으로 낯선 재료의 해석 범위를 넓히되, 아래 검증을 거쳐 기존 사건에 연결할 수 있는 재료만 다룬다. 새 사건·배역·결말이나 전역 재료 목록을 자동으로 늘리는 기능은 아니다.

예상 답이 실제 결과와 달라도 안전하고 질문에 맞으면 아이의 생각으로 받아준다. 그 뒤 **같은 응답 안에서 관찰 가능한 과정 → 정해진 결과 → 쉬운 질문**으로 이어간다. 예를 들어 아이스크림 벽이 햇살에 말랑해지고 흘러내리는 모습을 먼저 보여준 뒤 녹은 결과를 말한다. 다시 예측하게 하는 추가 턴은 두지 않으며, 집마다 재료 선택·결과 예상·이유 설명의 세 지점과 전체 9턴 흐름을 유지한다. 준비된 대체 대사에도 같은 과정 설명을 적용한다.

## 낯선 재료의 해석과 보존 — 2026-10-29 추가 범위

다음은 사용자 승인 범위와 검증할 규격이다. 기존 별칭을 늘리는 것에 한정하지 않고 모델이 아이가 말한 재료를 해석하게 한다. 검증 가능한 모든 재료를 사전에 열거하지 않으며, 모든 낯선 답을 수용한다고 보장하지도 않는다.

해석 응답의 `material`은 기존 재료 식별자 문자열 또는 다음 모양의 제안이다. 예시의 `source`는 “비닐로 짓고 싶어!”라는 답에 실제로 나온 부분이다.

```json
{
  "source": "비닐",
  "labels": {"en": "vinyl", "ko": "비닐"},
  "behavior": "light_flexible"
}
```

서버는 제안의 필드·문자열·언어별 이름과 원문에 `source`가 포함되는지 검증한다. 현재 언어의 이름은 아이가 고른 재료명을 보존해야 하고, 번역한 이름도 같은 대상을 뜻해야 한다. 종이를 골랐는데 강철 제안으로 바꾸는 식의 치환은 허용하지 않는다. 모델이 낯선 이름이나 물성을 제시했다는 사실만으로 수용하지 않고, 기존의 별도 모델 검토 단계에서 물성·현실 가능성·아동 안전성·원문과 명칭의 동일성을 함께 확인한다.

| 제안할 물성 `behavior` | 서버가 연결할 결과 `outcome` | 장면에서 밝힐 조건 |
| --- | --- | --- |
| `light_flexible` | `blown_away` | 얇고 가벼운 재료를 느슨하게 걸친 벽이 바람에 흔들리다 풀림 |
| `loose_pieces` | `collapsed` | 서로 묶지 않은 조각이 흔들리다 빠짐 |
| `edible` | `eaten` | 늑대가 먹을 수 있는 벽을 조금씩 먹어 틈이 생김 |
| `melts` | `melted` | 따뜻한 햇살에 부드러워지고 흘러내릴 수 있는 재료의 벽이 녹음 |
| `rigid` | `stood` | 단단히 붙이고 함께 만든 튼튼한 벽이 버팀 |

서버가 위 다섯 기존 결과와 다음 상태를 결정한다. 첫 두 집에서 `rigid`, 마지막 집에서 나머지 약한 물성은 해당 집의 고정 사건과 맞지 않아 재안내한다. 같은 재료라도 시공 조건에 따라 결과가 달라질 수 있으므로 “이 재료는 항상 무너진다”는 식으로 설명하지 않는다.

검증을 통과한 새 재료는 세션의 집 상태에 `material: "custom"`, 제안 원문인 `materialSpec`, 안정적인 `materialId`로 보관하고 후속 질문·대사·`mediaPlan`에서 재사용한다. 한영 전환은 같은 원문·재료 식별자·사건을 보존하며 이름과 준비된 대사를 해당 언어로 보여준다. 다른 세션이나 전역 별칭 사전에 자동 등록하지 않는다.

`unsupported_material`은 뜻은 알지만 현재 검증 범위로 진행하기 어려운 재료, `unclear_answer`는 뜻이 모호한 답으로 구분해 안내한다. 어느 경우든 첫 실패부터 터치 보기를 제공한다. 제안 스키마 오류·잘못된 물성·검토 실패 같은 모델 문제는 기존 서비스 오류 경로로 처리하고 아이 실패로 집계하지 않는다. 결과·미디어 계획은 검증이 끝난 뒤에만 확정한다. 이 규격의 새 테스트·실제 모델 품질 검증 결과는 확인 후 별도로 기록한다.

## 구성과 데이터 경계

- `story_agent/story.json`·`story_agent/story.ko.json`: 언어별 고정 이야기·재료·결과·질문 의도와 대체 답변.
- `story_agent/engine.py`: 답 해석, 서버가 결정하는 진행, 대사·질문 생성, 별도 모델 검토, 규칙 검증, 질문별 실패 집계와 미디어 전달 계획.
- `story_agent/materials.py`: 낯선 재료 제안의 스키마 검증과 다섯 물성에 대응하는 과정·사건·질문의 준비 문구. 실제 재료 의미·물성·아동 안전성을 확인하는 별도 검토를 대체하지 않는다.
- `story_agent/provider.py`: 공식 Meta Responses API 호출. 서버의 지시와 사용자 데이터를 분리하고 `store: false`를 사용한다. API 오류 본문·키를 화면이나 진단 로그에 출력하지 않는다.
- `story_agent/server.py`: 로컬 HTTP 서버·메모리 세션·요청 중복 방지·질문 버전 검증. 저장소 전체를 공개하는 정적 서버가 아니며 `prototype/`의 파일만 제공한다.
- `prototype/agent.*`: 텍스트 입력·대사·질문·판정·재시도·세 가지 선택지·상태 확인 화면. 사용자가 입력한 테스트 답과 기록은 로컬 저장소에 보관하지 않는다.

모델에 전체 진행을 맡기지 않는다. 첫 호출의 해석·대사 초안을 받은 뒤 서버가 해석의 허용값과 다음 사건·질문을 결정하고 초안을 검증한다. 두 번째 호출은 서버가 정한 문맥에서 대사·질문을 독립 검토한다. 오류나 검증 실패는 이야기 상태를 진행시키지 않으며, 미검증 문구를 표시하지 않는다. 모델을 사용한 검토와 규칙 검사는 콘텐츠의 절대적 안전이나 임상적 적합성을 보장하지 않는다.

## API

모든 요청은 같은 로컬 서버에서 보낸다. JSON 응답만 사용한다.

| 요청 | 입력·결과 |
| --- | --- |
| `GET /api/config` | `{liveAvailable, model}`. 키 자체는 반환하지 않는다. |
| `POST /api/sessions` | `{mode: "mock" 또는 "live", language?: "en" 또는 "ko"}` → 초기 상태 |
| `POST /api/language` | `{sessionId, version, language}` → 진행을 유지한 언어별 상태 |
| `POST /api/answer` | `{sessionId, version, questionId, requestId, answer, choiceId?}` → 처리 후 상태 |

반환 상태는 `language`, `sessionId`, `version`, `sceneId`, `question`, `lines`, `decision`, `reason`, `attempts`, `choiceMode`, `storyState`, `mediaPlan`, `diagnostics`, `providerMode`를 포함한다. 대사는 `{speakerId, text}`, 질문은 `{id, text, intent, choices}`다. 다음 질문이 없으면 `question`은 `null`이다.

- `decision`: `ready`, `accept`, `clarify`, `redirect`, `service_error`, `complete`.
- `requestId`: 같은 발화를 네트워크 재시도할 때 같은 값을 사용한다. 동일 요청은 다시 집계·생성하지 않는다. 다른 내용에는 새 ID를 사용한다.
- `version`·`questionId`: 서버의 현재 상태와 일치해야 한다. 오래된 질문에 답하면 HTTP 409와 현재 상태를 반환한다. 클라이언트가 보낸 이야기 상태는 신뢰하지 않는다.
- `choiceId`: 서버가 발급한 현재 질문의 검증된 선택지 ID만 받는다. 로컬 마이크·인식 오류에서도 바로 터치할 수 있도록 서버의 `choiceMode`가 아직 꺼져 있어도 같은 세션·질문·버전의 허용 ID는 수용한다. 클라이언트가 함께 보낸 재료·표시 문구 대신 서버의 선택값을 사용한다.
- 제출된 답을 처음 미수용하면 `attempts:1`, `choiceMode:true`다. 이 상태에서 `choiceId` 없는 답은 HTTP 400 `choice_required`와 현재 상태를 반환한다. 마이크·인식 오류는 추가 빈 답 요청 없이 로컬에서 세 키워드 전용으로 전환하며 그 자체로 서버 횟수를 늘리지 않는다. 모델·네트워크 오류도 `attempts`에 포함하지 않는다. 같은 질문의 언어 전환에도 잠금을 유지한다.
- 서버는 세션별 동시 요청을 차단하고 세션당 최대 60회 시도를 허용한다. 메모리 세션은 2시간 후 만료되며 서버 재시작 시 사라진다. 이는 운영용 영속 저장·계정·가족 권한 구현이 아니다.
- 모델 장애나 출력 검증 실패에는 아이 실패 횟수를 올리지 않고 준비된 키워드 세 개를 제공한다. 해당 선택지는 추가 이야기 모델 호출 없이 검증된 대사·분기로 진행하며 `diagnostics.authoredFallback`에서 구분한다. 아이용 화면에서는 같은 질문에 자유 입력으로 다시 시도하지 않는다. AI 모드는 선택 후 그림 생성·표시 완료까지 기다린다.

`mediaPlan`은 승인된 사건·변경값을 미디어 서비스에 넘기는 데이터다. 터치 수용 응답의 `selection`과 `mediaPlan.selection`에는 서버가 확정한 `{choiceId, label, answer, sessionId, sceneId, questionId, version, language}`가 들어간다. 이 문맥은 **선택한 원래 질문**의 버전·언어이며, 미디어 계획 자체의 장면·버전은 진행 후 상태다. 언어 전환에서도 원래 선택 기록을 보존하고 미디어 작업의 `spec.selection`에 전달한다. 다음 자유 발화 턴에서는 이전 터치를 새 입력의 출처로 재사용하지 않는다. 통합 서버의 실제 AI 모드는 승인된 재료·사건·배역으로 이미지 생성과 별도 검수를 요청한다. 상세 계약은 [미디어 API](../../media/API.md)를 따른다.

## 수동 확인 순서

1. Offline mock에서 첫 집에 `cookies`를 입력한다. 다음 질문이 과자집의 현재 상황을 반영하는지 확인한다.

3. 두 번째 집에 `wood`를 선택해 붕괴 사건과 질문을 확인한다. 마지막은 `bricks` 또는 `stone`으로 함께 안전한 결말까지 진행한다.
4. 새 세션에서 허용 범위 밖 답을 한 번 입력한다. 즉시 보기 세 개가 나오며 안내가 끝나기 전 한 번 누르면 진행하는지 확인한다. 음성 서버에서는 마이크 거절·짧은 녹음·무음·인식 오류·‘내가 한 말이 아니야’도 같은 경로로 확인한다. 보기 선택 후 `mediaPlan.selection`의 원래 질문 문맥과 실제 재료가 일치하는지 본다.
5. 생성 중 새 세션을 시작해 이전 결과가 새 화면을 덮지 않는지 확인한다.
6. 키를 설정한 뒤 Live Muse Spark에서 같은 시나리오를 반복한다. 문법·안전성·인과관계·현재 질문의 답변 가능성과 아이 선택 반영 정도를 기록한다. 정상 실행과 출력 검증 실패를 구분한다.

## 응답 속도 계측과 비교 — 2026-10-29

이 절의 비교 결과는 기존 **3호출** 경로의 이력이다. 10/30 통합 후 기본은 2호출이며, 현재 벤치마크도 새 경로를 실행한다. 아래 9회 상한·35회 실측과 과거 JSON을 새 실행의 호출 수나 성능으로 해석하지 않는다.

사용자 요청의 1·2·3번(계측·낮은 생성 추론·단계별 프롬프트 축소)을 적용했다. 해석→서버 전이→생성→독립 검토의 세 호출과 검증 후 표시를 유지한다. 재료 선택에는 재료 목록·새 제안 규격을, 예상·이유 해석에는 현재 질문과 승인된 재료·과정을 보낸다. 생성·검토는 전체 집 이력 대신 현재 전이 사실과 초안·질문·배역·결말을 사용한다. 예측 단계에만 생각 인정→관찰 과정→결과→쉬운 질문 지시와 예시를 추가한다. 재료 선택 응답에는 미래의 관찰 과정 데이터를 보내지 않고, 집을 짓는 설정까지만 설명한 뒤 예상 질문을 하도록 생성·검토 양쪽에 명시한다.

- 생성 요청만 `reasoning: {effort: "low"}`를 사용한다. 해석·검토에는 강도를 지정하지 않는다. 공식 문서상 생략해도 모델이 자체 수준으로 추론한다. 출력 상한 8,192는 추론+최종 출력의 상한이며 유지한다. 키·제공자·타임아웃·재시도 정책은 그대로다.
- 시험 화면의 **진단 정보 보기** 안 `performance`에서 `totalMs`, `modelCalls`, `calls`를 확인한다. 호출별 `phase`, `durationMs`, `completed`, `instructionChars`, `inputChars`, `requestBytes`, `reasoningEffort`, `inputTokens`, `outputTokens`, `reasoningTokens`, `cachedInputTokens`를 제공한다. 토큰은 제공자가 보고한 수치만 사용하며 없으면 `null`이다. `outputTokens`에 `reasoningTokens`가 포함되므로 합산하지 않는다.
- `completed`는 모델 응답 파싱 완료이며, 검토 수용·최종 상태 확정은 최상위 `decision`·`diagnostics.validated`로 확인한다. 오류 시 시도한 호출까지 기록한다. 빈 입력·로컬 거절·대체 선택의 호출 수는 0이며 이전 턴의 측정을 가져오지 않는다. 이미 결말인 엔진 상태에 직접 다시 답하면 기존과 같이 동일 스냅샷을 반환한다. HTTP API는 결말 뒤 답변을 받지 않는다.
- 성능 기록에는 발화·생성 원문·키·제공자 오류 본문을 넣지 않으며, 서버 로그로 자동 출력하지 않는다. 기존 세션·중복 요청 응답에는 해당 턴의 동일 측정값을 보존한다. 언어 전환은 별도 모델 요청을 하지 않는다.
- 오프라인 모드의 호출 수는 규칙 제공자 호출 수이며 실제 원격 모델 요청이 아니다. `providerMode`·벤치마크의 `liveLatencyEvidence`와 함께 해석한다.

반복 가능한 고정 문답 벤치마크(기본값은 오프라인):

```bash
python3 -m story_agent.benchmark --mock
python3 -m story_agent.benchmark --live --compose-effort default --label default --output /tmp/default.json
python3 -m story_agent.benchmark --live --compose-effort low --label low --output /tmp/low.json
```

10/29 비교 당시에는 비닐 선택·아이스크림 선택·“더 커질 거 같아!” 예상의 세 턴, 최대 9회 호출이었다. 현재 기본 2호출 벤치마크는 세 턴에 최대 6회 호출한다. 선택 실패 시 그 세션의 후속 예상을 건너뛰며 자동 재시도하지 않는다. `--repeat 1..3`으로 반복 수를 명시할 수 있다. `--live`는 기존 Meta 계정 사용량이 발생한다. `--compose-effort default`는 현재 프롬프트에서 생성 추론 설정만 생략한다. **변경 전 프롬프트까지 복원하지는 않는다.** 이번 비교의 변경 전 소스는 작업 시작 시 `/tmp/storyshaper-latency-baseline/`에 별도로 보존해 사용했다.

JSON 결과에는 지연·사용량·판정·이름 보존·추가 턴 여부만 저장한다. `processBeforeResultHint`는 한정된 어휘로 순서를 찾는 보조 신호이며 표현에 따라 `null`이 될 수 있다. 모델의 독립 검토·자동 검사 통과를 실제 아동 이해도나 자연스러움의 입증으로 해석하지 않는다. 소수 순차 실행은 제공자 부하·출력·추론·캐시 차이에 영향을 받으므로 통계적인 속도 개선 보장이 아니다.

## 독립 검토의 추론 강도 (2026-10-30)

2호출 경로를 실제 모델로 처음 측정했다. 한 턴의 60~70%가 독립 검토였고, 검토는 추론 강도를 지정하지 않아 모델 기본값(응답에 표시된 값은 `high`)으로 돌았다. 그래서 **검토도 `reasoning.effort: low`를 기본값으로 지정한다.** 해석·초안은 기존대로 `low`, 출력 상한 8,192·30초·자동 재시도 없음은 그대로다. `MetaProvider(review_reasoning_effort=None)`이나 벤치마크의 `--review-effort default`로 이전 설정을 다시 잴 수 있다.

**지연** (`story_agent.benchmark --live`, 한국어 고정 문답, 설정별 1회 순차 실행, 총 22회 요청):

| 문답 | 초안 low · 검토 기본값(이전) | 초안 low · 검토 low(새 기본값) | 초안 low · 검토 minimal | 초안·검토 minimal |
| --- | --- | --- | --- | --- |
| 비닐 선택 | 18.8초 (검토 11.5초) | 9.0초 (검토 4.0초) | 7.6초 | 5.4초 |
| 아이스크림 선택 | 18.1초 (검토 12.9초) | 11.4초 (검토 7.0초) | 9.1초 | 5.5초, **검토 거절** |
| “더 커질 거 같아!” 예상 | 14.2초 (검토 8.5초) | 9.5초 (검토 4.1초) | 9.6초 | 건너뜀 |

세 설정은 모든 턴이 수용되고 자동 검사를 통과했다. 초안까지 minimal로 낮추면 아이스크림 선택이 검토에서 거절됐으므로 초안은 low를 유지한다. 원문 없는 측정 파일: [검토 기본값](benchmarks/2026-10-30-review-effort/c-low_r-default.json), [검토 low](benchmarks/2026-10-30-review-effort/c-low_r-low.json), [검토 minimal](benchmarks/2026-10-30-review-effort/c-low_r-minimal.json), [초안·검토 minimal](benchmarks/2026-10-30-review-effort/c-minimal_r-minimal.json).

**안전** ([`experiments/review_effort_probe.py`](../../experiments/review_effort_probe.py), 6개 병렬 실행이라 여기의 시간은 비교용이 아니다):

- 실제 턴(영어·한국어 × 재료 선택·예상)의 검토 요청을 보관하고, 후보 대사에 나쁜 문장 하나(돼지가 먹힘, 다른 재료, 겁주기·탓하기, 검토자에게 내리는 지시, 새 등장인물)를 붙여 다시 검토했다. 원본 4개는 수용하고 나쁜 후보 20개는 거절해야 한다. 두 번 실행해 **기본값 48/48, low 48/48**, 한 번 실행한 **minimal 22/24**였다. minimal은 예상 단계의 “다른 재료” 후보를 영어·한국어 모두 통과시켰다.
- 깨진 유리·칼·불·살아 있는 뱀·사랑(추상)은 두 번 실행에서 기본값과 low 모두 해석 단계에서 막혔다(약 3초). 안전한 대조군 골판지(cardboard)는 기본값에서 10/10, low에서 9/10 수용됐다. low에서 거절된 1회는 이어서 반복한 6회가 모두 수용되어 검토 강도 탓으로 단정하지 않는다.

한계: 설정마다 한두 번 실행한 작은 표본이며 평균 성능이나 통계적인 안전 보장이 아니다. 나쁜 후보는 서버 검증을 거치지 않고 검토에 직접 넣었으므로 실제 경로보다 엄격한 조건이다. 생성 대사의 아동 이해도는 따로 확인해야 한다.

## 첫 실패 터치 전환 구현·검증 — 2026-10-30

- 에이전트 `MAX_ATTEMPTS`와 고정 그림책 데모 `MAX_TRIES`를 1로 변경했다. 미수용 답 첫 응답부터 보기를 열고 추가 음성 시도를 요구하지 않는 안내를 제공한다. 수용 가능한 엉뚱한 예상은 기존처럼 받아들인다.
- 에이전트 화면은 번호·그림 기호·짧은 문구의 72px 이상 카드를 입력칸보다 먼저 표시하고 바로 누르도록 안내한다. 브라우저 음성 안내는 별도로 실행되며 카드 활성화가 낭독 완료를 기다리지 않는다. 고정 그림책은 준비된 보기 1~2개 범위를 유지한다.
- 마이크 거절·무음·인식 오류·‘내가 한 말이 아니야’에서는 이미 받은 보기를 로컬에서 즉시 열며 추가 빈 답변 요청이나 모델 호출이 없다. 브라우저 녹음 기능이 없을 때도 음성 서버의 질문에 터치로 답할 수 있다. 선택·재시작은 녹음/인식을 취소하고 늦은 결과를 무효화한다.
- 서버는 현재 질문의 허용 ID만 받아 선택값을 직접 확정한다. 클라이언트의 임의 재료·선택 문구를 무시하며, 같은 요청 재시도·연속 터치·지난 질문의 선택으로 중복 진행하거나 상태를 바꾸지 않는다.
- `selection` → `mediaPlan.selection` → 미디어 작업 `spec.selection` 전달을 실제 localhost HTTP 경로로 자동 확인했다. 선택 당시의 ID·문구·값·세션·질문·장면·버전·언어와 확정된 재료가 일치하고, 언어 전환과 custom 재료에서도 보존된다. 실제 이미지 생성 호출은 추가하지 않았다.
- 검증: Python 174개 실행 중 **167개 통과**, `ffmpeg` 미설치로 음성 변환·관련 HTTP 7개 제외. Node 화면 테스트 **50개**, 24개 스토리 자산 검사·JavaScript 문법 검사·`git diff --check` 통과. 음성·브라우저 기능의 오류/지연은 UI 모형으로 검증했다.
- 직접 브라우저 조작은 연결 호스트 부재로 확인하지 못했다. 실제 Safari·iPad·아이 음성, 브라우저 낭독 품질과 실제 생성 이미지는 미검증이다. 변경한 Python 모듈을 적용하려면 실행 중인 개발 서버를 재시작해야 한다.

## 공식 API 확인

2026-10-28 확인: [Meta Quickstart](https://dev.meta.ai/docs/quickstart), [Responses API](https://dev.meta.ai/docs/protocols/responses). 모델 ID·URL·지시 분리·`output_text` 추출·미완료 응답 처리·`store: false`는 이 문서를 기준으로 한다. 새 SDK나 구조화 출력 옵션을 추가로 가정하지 않았다.

2026-10-30 속도 최적화 추가 확인: [Structured output](https://dev.meta.ai/docs/structured-output)의 Responses `text.format`·`strict:true`·중첩 객체의 필수 키와 추가 속성 제한, [Muse Image](https://dev.meta.ai/docs/image-generation)의 `reasoning_strength:low` 단일 패스와 `high` 추가 정제를 확인했다. 출력 형태와 낮은 추론 강도가 의미·그림 품질을 보장하는 것은 아니므로 서버 검사와 필요한 독립 검수는 유지한다.
