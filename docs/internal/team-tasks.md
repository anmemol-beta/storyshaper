## 팀 결정이 필요한 문제

코드와 측정 기록(`api-test.md`, 나레이션 클립 길이)을 대조해 찾았다. 실제 파이프라인을 붙이면 "아이의 말이 그림과 이야기를 바꾼다"는 약속이 깨지는 지점이다.

- [ ] **원작을 아는 아이의 답.** 이야기 구조상 첫째·둘째 집은 무너져야 하는데, 첫 질문에 "Bricks!"라고 답하는 경우의 분기가 없다. 영어 원작의 둘째 집은 *sticks*인데 `p2`는 "Wood!"만 받는다. 정답을 일찍 말한 아이를 어떻게 이야기에 살릴지, 동의어를 어디까지 받을지 정한다(로드맵 4절 69행이 문제만 언급).
- [ ] **지연 숨기기의 실제 숫자.** 예상 밖 재료 하나에 그림 두 장이 연달아 필요하다(집 → 그 집을 편집한 늑대 장면). 측정치로 STT 3초 + 그림 12~20초 + 그림 12~20초 = 27~43초인데, 그사이 낭독은 `b1paper` 4.3초 + `d1` 3.0초 정도다. 질문 시점에 예상 답 그림을 미리 만들지, 몇 개까지 만들지(크레딧), 대기 화면을 어떻게 채울지 정한다. 이미지당 가격은 아직 확인하지 못했다.
- [ ] **Spark가 아이 답을 원작대로 고친 기록**(`api-test.md`, reasoning low). 재료는 Spark 자유 생성이 아니라 구조화 출력으로 뽑고 서버가 허용값을 검증하는 방식으로 설계한다(로드맵 4절).
- [ ] **장면 데이터 일반화.** `LABEL`, `MATERIAL_ICON`, `wolf_${h1}` 이미지, 나레이션 목록이 재료 4개에 묶여 있다. 새 재료가 들어오면 "His undefined was finished!"가 나오고 늑대 이미지가 깨진다. 생성 이미지 URL을 어디서 받을지는 서버 API에 달려 있으므로 서버 설계와 함께 바꾼다.
- [ ] **실제 아이 목소리 STT.** 지금까지는 Mac 합성 음성의 한국어로만 시험했고 단어 중복이 있었다. 영어로 말하는 아이 목소리로 시험한다.
- [ ] **iPad 실기기 확인.** 부모 목소리 재생(PR #4에서 iOS 대응), 마이크 권한(HTTPS 필요), 그림 카드 터치.
