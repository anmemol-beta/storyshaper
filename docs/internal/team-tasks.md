## 담당과 첫 통합 범위

| 담당 | 확정된 기능 |
| --- | --- |
| 현준님 | 부모 목소리·배역 음성·낭독 등 음성 개발 |

위 기능 담당은 확정이다. 음성 인식·포맷 변환, API·파일 경계, 공통 저장소·인프라의 세부 배정은 로드맵 §12의 **연결 제안**을 바탕으로 통합 전에 합의한다. 팀 대표·데모 담당과 제출 명단의 확인도 남아 있다.

첫 제출 묶음은 **실제 동작하는 첫 편 + 부모 목소리 + 핵심 독서 UI**를 우선 연결하고, 채택한 image to video의 대표 장면을 검증한다. 실제 제출에 포함할 세부 범위는 통합 결과로 정한다. 10/30(금) 중간 통합은 회의 계획이며, 주말 안정화·11/2 데모 준비는 내부 목표다.

## 현재 확인된 구현

아래의 3회 실패 전환 기록은 이전 구현의 이력이다. **10/30 후속 개발로 첫 실패 즉시 터치 전환·선택 검증·미디어 전달을 로컬 구현하고 자동 검증했다.** 실제 기기·실제 음성·유료 이미지 생성의 전체 연결은 후속이다.

- [x] **첫 실패 즉시 터치 복구:** 답변 미수용 첫 1회, 마이크 거절·무음·인식 오류·오인식 취소 시 즉시 카드를 표시·활성화한다. 안내 낭독 중에도 한 번 터치로 진행하며, 검증된 선택 ID·문구·값·원래 질문 문맥을 `mediaPlan.selection`과 미디어 작업 `spec.selection`에 연결한다. 중복 터치·언어 전환·늦은 인식 응답의 자동 회귀 검증을 포함한다. 실제 기기 확인은 미완료다.

- [x] **단계 1의 텍스트 입력 시험:** `story_agent/`와 `prototype/agent.html`에 사람이 작성한 장면·재료·질문 메타데이터, 서버가 결정하는 상태 전이, 답 해석·대사/질문 생성·출력 검토를 연결했다. 로컬 메모리 세션, 요청 중복 방지, 질문 버전 검증과 시도 제한이 있다. 운영용 영속 저장·계정·가족 권한이 구현된 것은 아니다.
- [x] **텍스트 가드레일·복구 검증:** 에이전트는 질문별 입력 실패를 합산하고 세 번째 실패 직후 검증된 보기 세 개를 제공한다. 서비스·모델 오류는 아이 실패 횟수에서 제외하며 준비된 선택지로 진행할 수 있다. 영어·한국어 각각 50가지 허용 재료 조합의 오프라인 완주와 자동 테스트 54개, 실행 방식·연결 상태 UI 테스트 4개의 기록이 있다.
- [x] **실제 Muse Spark 연결 기록:** 2026-10-28 과자집 → 나무집 → 벽돌집의 한국어 9턴을 실제 모델로 완주했다. 해석·생성·검토를 통과했고 준비된 대체 대사를 쓴 경로가 아니었다. 모든 재료 조합·언어·대상 연령의 생성 품질을 검증했다는 뜻은 아니다.
- [x] **기존 고정 그림책:** 준비된 그림과 분기, 영어 부모 목소리 클립 40개, 읽기 속도 조절이 있다. 영어·한국어 전환을 지원하며 한국어 낭독은 브라우저 음성이다. 이 화면의 마이크와 그림 변경은 모의 동작이다.
- [x] **PR #6 병합:** 기존 영어 `prototype/story.js`의 장면 연결·도달 가능 여부·이미지·사전 생성 낭독 파일을 검사하는 `experiments/check_story.mjs`와 README 정리를 반영했다. 실제 에이전트의 모델 출력이나 한국어 음성 품질을 검사하는 도구는 아니다.
- [x] **PR #4 병합:** 기존 한영 전환·진행 상태를 보존하면서 질문별 3회 실패 그림 카드, 인식 결과 되돌리기, 텍스트 안전 표시, 오디오 재사용과 낭독 완료 후 화면 전환을 통합했다. 고정 그림책은 준비된 보기 1~2개를 유지하고 실제 에이전트의 서버 판정·보기 세 개는 유지하는 방안을 사용자 승인에 따라 반영했다. 그림책 회귀 테스트 24개와 기존 에이전트 UI 테스트 4개가 통과했다. 실제 iPad 재생 검증은 별도다.

새 이미지·영상 생성, 실제 마이크·STT, 동적으로 생성한 대사의 부모 목소리 낭독을 하나로 연결하는 작업은 아직 남아 있다. `mediaPlan`은 후속 담당자에게 전달할 승인된 데이터이고, 시험 화면 그림은 고정 참조 이미지다. 실행·상세 검증 근거와 한계는 [시험 가이드](story-agent.md)에서 관리한다.

## 통합할 때 결정·검증할 문제

- [ ] **선택과 사건의 인과관계:** 첫 두 집의 필수 사건은 피난처를 잃고 형제에게 이동하는 것이다. 에이전트는 벽돌·돌을 첫 두 집의 다른 허용 재료로 유도하고, 과자·아이스크림은 사전 설계한 사건으로 처리한다. 이 규칙을 기존 그림책·미디어·낭독과 일치시킨다. 새 재료나 사건의 무제한 자동 추가는 현재 범위가 아니다. 실제 아이 표현·동의어의 수용 품질도 확인한다.
- [ ] **대기 시간·비용:** 과거 개별 실험에서 STT 약 3초, 이미지 한 장 12~20초가 측정되었고, 실제 에이전트의 한국어 한 턴은 해석·생성·검토 세 요청으로 약 18~29초였다. 서로 다른 실험 수치를 전체 파이프라인 성능으로 합산하지 말고 통합 후 측정한다. 예상 답 사전 생성·캐시 범위, 대기 화면과 실패 대체 경험을 예산에 맞춰 정한다.
- [ ] **미디어·낭독 전달 규격:** 에이전트의 승인된 `mediaPlan`과 화자별 대사를 그림·영상·낭독 서비스에 연결한다. 고정 그림책의 `LABEL`·이미지명·사전 생성 낭독 목록은 에이전트의 새 결과를 자동 처리하지 않는다. 장면·질문·요청·분기 버전·언어·화자 식별자와 오래된 결과 차단 방식을 맞춘다.
- [ ] **실제 아이 목소리·iPad:** 브라우저 녹음·포맷 변환·STT·인식 확인·재녹음, 질문별 혼합 실패 집계와 카드 표시·낭독을 실제 기기에서 검증한다. 마이크 권한 거절·무음·소음·중복 탭·낭독 중 녹음과 재생 중단도 포함한다.

## 남은 개발 순서

최신 복구 요구사항은 [로드맵 §4](development-roadmap.md#첫-실패-즉시-터치-객관식-전환--2026-10-30-사용자-수정)를 따른다.

1. [ ] **연결 규격·제품 기준 합의:** 현재 텍스트 시험의 상태·오류·대체 응답 예제로 각 서비스 경계를 맞춘다. 서버의 저장·복구·가족별 접근 통제·작업/비용 제한은 배포 범위에 맞춰 보강한다.
2. [ ] **마이크 → Muse Voice Transcribe → 에이전트 → 터치 보기의 실제 기기 검증:** 첫 실패 즉시 카드 표시·터치 안내·한 번 누르기와 서버·모델 장애 미집계는 코드·자동 테스트에 반영했다. `ffmpeg` 설치 환경의 음성 변환과 iPad·실제 아이 목소리에서 전체 경로를 확인한다.
3. [ ] **에이전트 → 실제 그림·영상:** 검증된 선택 기록과 재료·사건을 미디어 작업에 전달하는 HTTP 경로는 구현했다. 다음은 실제 이미지 생성에 같은 선택이 반영되는지 검증하는 작업이다. 지연·실패 시 검증된 정지 이미지로 진행하게 한다. 생성 중 재시작·페이지 이동·과거 답 변경에서 오래된 결과가 적용되지 않는지 확인한다.
4. [ ] **부모 목소리·배역 낭독:** 동의·등록·미리 듣기·재녹음·삭제, 고정 대사 사전 생성·예상 밖 대사 생성, 기본 음성 대체와 캐시·파생 음성 삭제를 연결한다. 기존 준비 음성 재생을 이 등록·생성 흐름의 완료로 보지 않는다.
5. [ ] **독서 UI 완주·저장/재개:** 첫 편을 실제 입력부터 끝까지 연결하고 보호자 설정, 페이지 이동·일시정지·이어 읽기·오류 복구를 검증한다. 실제 iPad 음성·영상 재생도 확인한다.
6. [ ] **실제 모델·사용성 평가:** 허용 재료·잘못된 예측·안전하지 않은 답·불가능한 요청·서비스 장애를 반복 확인한다. 질문 이해·교육 효과·기다리는 시간과 낭독 품질은 별도 평가하며 한 차례의 실제 완주로 완료 처리하지 않는다.
