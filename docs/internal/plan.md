# 기획 메모

> 2026-10-27 추가 요구사항과 개발 우선순위는 [개발 기능과 개발 순서](development-roadmap.md)에 기록했다. 2026-10-28 회의에서 확정한 개발 담당과 통합 계획은 해당 문서 §12 및 [회의록](../meetings/README.md)을 따른다. 아래 단일 동화 중심 범위는 초기 기획 기록이며, 전체 제품 범위는 새 계획을 기준으로 한다.

## 한 줄 문제 정의 (후보)

| 안 | 문장 | 비고 |
|---|---|---|
| **A (추천)** | Kids today *watch* stories on endless autoplay; they rarely get to *shape* one. | 숏폼, 상상력, 말하기 능력을 묶음. 그림이 바뀌는 핵심 기능과 바로 연결 |
| B | Working parents want to read with their kids every night, but long hours make it impossible. | 데모 영상 스토리로 활용 |
| C | In multilingual families, kids lose the parent's language because there are no stories in it they can engage with. | 다국어 음성 필요. "다음 단계"로 |

## 왜 만드나

- 부모가 새벽 출근과 야근으로 책을 읽어줄 시간이 없다.
- 다문화 가정에서 아이가 부모의 언어를 잘 배우지 못하는 경우가 있다.
- 반대로 부모의 한국어 입력이 제한되면 아이가 풍부한 한국어 그림책 읽기를 충분히 듣지 못한다. 2025년 초·중·고 이주배경 학생은 20만 명을 넘었다(전체 4.0%, 초등 5.0%). 앱이 또렷한 한국어 낭독과 한국어 대화로 이를 보완하고, 엄마 목소리로 한국어를 읽는 방향도 검토한다(10/30 현준님 제안, 상세: 로드맵 §6 다문화 가정).
- 아이들이 자극적인 숏폼을 수동적으로 보는 시간이 길어지고 있다.
- 그림책은 비싸다.

## 동작 예시 (아기돼지 삼형제)

입력은 음성으로만 받는다. 타이핑은 받지 않는다.

1. 동화: "첫째 돼지 집이 바람에 날아갔어. 왜일 것 같아?"
2. 아이: "가벼워서!"
3. 동화: "맞아! 그럼 뭘로 만들었을까?"
4. 아이: "종이!"
5. 원래 짚집 대신 종이집이 그려지고 이야기가 이어진다.

나중에 붙일 수 있는 것: 아이가 그린 그림을 사진 찍어 넣기 (SAM 3.1로 캐릭터 분리), 동화 속 인물과 전화하기, 부모 목소리로 읽어주기, 여러 언어.

## 아직 정할 것

1. **아이 말을 언제 받을까**
   - A. 정해진 지점에서만 (룰 기반). 10일 안에 가능하지만 장면 설계가 많다.
   - B. 아무 때나 끼어들기 (AI가 이야기 변경). 재밌지만 이야기가 산으로 갈 위험.
   - **절충 (제안):** 질문 지점과 결말은 고정, 지점에서 나온 답의 해석과 그림 반영은 AI가 맡는다. "집의 재료는 (  )"에서 빈칸만 아이가 채운다.
   - 에피소드 1개(아기돼지 삼형제)를 완성도 있게 만드는 것을 목표로 한다.
2. **부적절한 답 처리:** 검증용 AI를 중간에 둔다. 막기보다 이야기 안으로 자연스럽게 돌린다.
3. **속도:** 영상 대신 이미지 + 음성으로 시작한다.
4. **플랫폼:** iPad 전용 언급. 웹/앱 미정.
5. **발달 단계별 참여 방식 (10/30 현준님 제안):** 대상 4~7세는 유지하고, 질문에 답하기 어려운 아이를 듣기만 하게 두기보다 같은 책에서 질문 난이도와 답하는 방법을 바꾼다. 듣기(2~3세, 확장) → 고르기(3~4세, 처음부터 그림 카드) → **대화(4~6세, 기본, 현재 흐름)** → 만들기(6~7세, 행동까지 바꾸기). 제출물은 "4~7세, 기본은 대화 단계"로 명시하자는 제안. 상세: [로드맵 §4 발달 단계별 참여 방식](development-roadmap.md#발달-단계별-참여-방식--2026-10-30-현준님-제안-미확정).

## 결정 기록

### 대본의 성격·감정을 이미지와 음성에 적용 (10/31 사용자 후속 요청)

- 정리한 대본을 실제 이미지 생성의 표정·몸짓 지시와 검수, 음성 합성의 인물별 강도·속도에 연결한다. 같은 표현 원본을 배역별 연기 녹음 안내와 학습 자료의 레이블로 사용한다.
- 이미지의 참조·생성 지시, 음성의 표현 프리셋, 실제 녹음에 의한 추가 학습을 구분한다. 현재 없는 연기 녹음을 만들어 학습 완료로 표시하지 않으며, 실제 녹음·전사·연기 확인을 거친 자료만 학습 경로로 넘긴다. 상세는 [로드맵 §4](development-roadmap.md)와 [표현·학습 안내](model-performance.md)를 따른다.

### 모든 인물이 말하는 대본과 공통 모델 입력 (10/31 사용자 요청)

- 내레이션 중심의 첫 편을 돼지 삼형제와 늑대가 직접 말하는 이야기로 바꾼다. 인물별 성격과 각 멘트의 화자·말투·감정을 한·영 JSON에 기록하고, 현재 개발본의 오프라인·AI 버전에 함께 적용한다.
- 추후 음성 학습·스토리 에이전트·이미지 생성에서 같은 인물을 참고하도록 발화 원문과 연기·성격 정보를 분리한다. 선택 재료의 사건·9턴·협력과 안전한 결말은 유지한다. 상세 입력 규격과 검증 범위는 로드맵 §4 및 [대본 안내](../../story_agent/README.md)를 따른다.

### 객관식은 오프라인 버전의 저장 그림 사용 (10/31 사용자 확정)

- 정해진 객관식 답은 AI 버전에서도 저장소에 있는 오프라인 버전의 장면 그림을 바로 불러온다. 이미 Git에 저장된 재료별 완성·사건 그림과 빈 터·결말을 재사용해 이미지 생성 대기를 줄인다.
- 서버에서 검증한 선택과 진행 후 장면에 정확히 맞는 그림만 사용하며, 그림 디코딩·전환이 끝나면 다음 질문과 입력을 연다. 자유 입력과 저장 그림이 없는 새 재료는 기존 생성 경로를 유지한다. 이는 아래 ‘승인된 새 답마다 생성’과 ‘준비 그림은 AI 진행을 열지 않음’ 규칙의 객관식 예외다. 상세 규격·완료 기준은 로드맵 §6을 따른다.

### 아이용 독서 화면과 입력 잠금 (10/31 사용자 설명 보완)

- 기본 화면은 데모용 `live.html`의 아이용 그림책 UI를 사용하는 `prototype/index.html`이다. 기존 개발용 `agent.html`은 보존하되 앱 UI에서 연결하는 버튼·링크를 두지 않는다. `python3 -m src.server`와 기본 8000은 유지한다.
- 기존 Demo 선택의 표시명을 **오프라인 버전**으로 바꾸고 **AI 버전**과 함께 제공한다. 오프라인 이야기는 준비된 규칙·그림을 사용하며, 음성 입력 자리의 고르기 버튼은 준비된 세 키워드를 연다.
- 승인된 다음 장면의 그림이 디코딩·화면 전환까지 끝난 뒤 새 본문·질문을 열고 답 입력을 허용한다. AI 생성 실패나 준비 그림 대체는 이 잠금을 해제하지 않는다. 10/31 재로딩 무반응 수정: 다운로드·디코딩 실패는 기존 그림을 다시 불러오고, 생성 실패는 명시적 버튼 클릭에 한해 새 생성·독립 검수를 요청한다. 같은 장면에서 최대 두 번 수동 재생성하며 연속 클릭·요청 재전송은 같은 작업을 재사용한다. 자동 유료 재시도는 하지 않는다.
- 첫 미수용 답·녹음/인식 실패 후에는 같은 질문의 마이크·글·카메라를 숨기고 세 키워드 터치만 허용한다. 언어 변경·다시 듣기로 자유 입력을 다시 열지 않는다. 이 결정이 아래 과거 기록의 이미지 대기 중 입력·선택적 재녹음·개발 UI 기본 화면을 대체한다.

### 앱 주소와 기본 화면 통합 (10/31 이전 요청 기록)

- 후속 사용자 요청으로 공식 실행 명령은 **`python3 -m src.server`**로 통일한다. `src.server`는 기존 통합 서버를 호출하는 진입점이며 기능별 구현을 복제하거나 이전하지 않는다. 기본 포트는 8000이다.
- 사용자 요청으로 최신 통합 앱은 `python3 -m src.server`, 접속 주소는 `http://127.0.0.1:8000/` 하나로 정한다. 이전 8002·8003 등 중복 앱 서버는 종료한다.
- 기존 8003에서 사용하던 전체 기능 화면을 `prototype/index.html`로 옮기고 `prototype/agent.html`은 삭제한다. 이야기·그림·음성 입력·카메라·첫 실패 터치·부모 음성 연결·진단 기능을 보존하고 기본 화면에 부모 음성 설정 링크를 둔다.
- 기본 주소는 필요한 스크립트가 올바르게 로드되는 `/prototype/index.html`로 연결한다. 앱 시작 안내와 데모 스크립트도 같은 8000을 사용하며, 부모 음성의 별도 처리 서비스 등 기능 의존 모듈은 중복 앱 서버와 구분한다.

### 응답 속도 최적화: 일반 경로 1호출과 선택적 독립 검토 (10/30 후속 확정)

- 사용자 요청으로 앞선 조사에서 제안한 선택적 검토 경로를 구현한다. 앱 기본은 `adaptive`이며, 등록 재료의 단순 선택과 관찰 과정이 확인되는 예상 응답은 서버 검사 뒤 1호출로 진행한다. 낯선 재료·복잡한 답·이야기 이동·결말은 별도 검토를 유지한다. 새 재료 수용 범위를 줄이거나 모든 답을 무조건 1호출로 바꾸지는 않는다.
- 초안과 필요한 검토의 추론은 `low`를 유지하고, 중복 장면 문맥과 출력 형식 오류를 줄인다. 실시간 그림은 빠른 `reasoning_strength: low`와 기존 독립 이미지 검수를 함께 사용한다. 이전 `two_call`·그림 `high` 설정은 비교용으로 선택할 수 있다.
- 호출 수·요청 크기는 오프라인으로 검증하며 실제 Muse 속도·자연스러움은 사용자 시험으로 확인한다. 상세 동작과 실행·비교 방법은 [시험 가이드](story-agent.md#선택적-독립-검토와-속도-최적화--2026-10-30)를 따른다. 아래 2호출 결정은 이전 경로의 기록이다.

### 답마다 실시간 그림 생성과 시험 화면 통합 (10/30 기록, 대기 중 입력 규칙은 10/31 변경)

- 사용자 요청으로 `prototype/agent.html`에서 새 답이 승인될 때마다 실제 Muse Image 편집을 요청한다. 준비된 장면만 교체하는 방식에서 실시간 생성으로 범위를 갱신한다.
- 마이크 녹음·Muse 전사, 기존 카메라·부모 목소리 경로를 같은 시험 화면에서 사용한다. 첫 실패 즉시 터치 선택 규칙을 유지하고, 이미지 대기 중에도 다음 답을 입력할 수 있다.
- 검증된 재료·행동·등장인물만 그림에 전달하고 별도 이미지 검수 뒤 표시한다. 중복 요청·언어 전환은 같은 작업을 재사용하며 실패·이전 그림을 새 생성 성공으로 표시하지 않는다. 세부 규격과 검증은 로드맵 §6과 시험 가이드를 따른다.

### 첫 실패 직후 터치 객관식으로 전환 (10/30 후속 수정)

- 답변이 올바르게 수용되지 않거나 음성 인식 실패 등이 **한 번이라도 발생하면 즉시 객관식으로 전환**한다. 이전의 3회 누적 기준을 대체한다.
- 같은 터치 화면에 보기를 바로 표시·활성화하고 “마음에 드는 걸 톡 눌러 줘!”처럼 짧게 안내한다. 추가 발화·재녹음이나 낭독 완료를 기다리지 않고 아이가 한 번 눌러 답할 수 있게 한다.
- 아이가 누른 선택과 장면 문맥을 보존하고, 서버가 검증한 선택값·재료·사건을 추후 이미지 생성 쪽으로 전달한다. 상세 기준과 완료 조건은 [로드맵 §4](development-roadmap.md#첫-실패-즉시-터치-객관식-전환--2026-10-30-사용자-수정)를 따른다.
- 후속 요청으로 첫 실패 전환·터치 UI와 검증된 선택 데이터의 미디어 전달을 구현하고 자동 검증했다. 실제 기기·실제 음성·유료 이미지 생성의 전체 연결 검증은 미완료다.

### PR 통합과 호출 방식 선택 (10/30)

- 사용자 선택으로 새 재료 수용·미지원 사유 구분을 유지하고 기존 재료를 재시도 예시로 안내한다. 새 재료의 그림이 없으면 미지원 상태를 보여 주며 같은 재료로 이야기를 진행한다.
- 기본 모델 경로를 답 해석·초안 생성과 독립 검토의 **2호출**로 바꾼다. 서버가 상태 전이·질문 식별자·선택지를 결정하며 검토 전에는 결과를 확정하지 않는다. 상세 규격은 [로드맵 §4](development-roadmap.md#4-동화-엔진과-가드레일), 구현·검증 한계는 [시험 가이드](story-agent.md)를 따른다. 과거 3호출 실측을 새 경로의 품질·속도 근거로 사용하지 않는다.

### 낯선 재료와 과정 설명의 품질 개선 (10/29)

- **대상과 문제:** 사용자 확인으로 대상 연령을 4~7세로 정했다. 실제 모델 시험에서 “비닐로 짓고 싶어!”를 못 알아들었다고 반복 안내한 사례와, 아이스크림집이 더 커질 것이라는 예상 뒤 관찰할 과정 없이 녹은 결과와 추상적인 질문으로 넘어간 사례를 개선한다.
- **재료 해석 범위 확대:** 비닐 하나를 등록 목록에 추가하는 데 그치지 않고 낯선 재료 전반을 해석한다. 아이가 말한 이름을 보존한 제안을 서버가 검증하고, 기존의 별도 모델 검토에서 물성·현실 가능성·아동 안전성과 명칭의 동일성을 확인한다. 검증된 다섯 물성을 기존 사건에 연결하며 고정 사건·등장인물·협력·안전한 결말은 유지한다. 세션 안에서 선택한 재료를 보존하되 전역 재료 목록을 자동으로 확장하거나 모든 재료의 수용을 약속하지 않는다.
- **같은 응답 안에서 과정부터 설명:** 아이의 안전한 예상을 짧게 인정하고 관찰할 수 있는 변화 → 결과 → 쉬운 질문으로 이어간다. 힌트 뒤 새 답을 요구하는 추가 턴은 두지 않고 집마다 세 참여 지점·총 9턴 흐름을 유지한다. 실제 생성과 준비된 대체 대사에 같은 원칙을 적용한다.
- **판정과 검증:** 당시에는 지원하기 어려운 재료와 뜻이 모호한 답의 안내를 구분하되 기존 입력 실패 집계·3회 보기 전환을 유지했다. 전환 시점은 위 10/30 후속 수정으로 첫 실패 즉시 전환으로 변경했다. 모델의 제안·검토 오류는 아이 실패로 세지 않는다. 상세 규격·완료 기준은 [로드맵 §4](development-roadmap.md#4-동화-엔진과-가드레일), 실제 문답·검증 기록은 [에이전트 시험 가이드](story-agent.md#품질-피드백--2026-10-29)에서 관리한다. 이번 결정은 실제 모델 품질·아동 이해도나 후속 미디어 통합의 검증 완료를 뜻하지 않는다.

### 에이전트 시험 범위와 질문 방식 (10/28)

- 사용자 요청으로 동화 에이전트의 텍스트 입력 시험을 먼저 개발한다. 페르소나와 성능·교육적 결과 최적화는 이후 진행한다.
- 참여 지점과 질문 목적·허용 범위는 고정하고, 실제 질문은 아이의 선택과 실제 사건에 맞게 생성한다. 과자집을 늑대가 먹었다면 바람에 날아간 이유를 묻지 않는다.
- 첫 두 집의 주요 사건은 피난처를 잃고 형제에게 이동하는 것으로 정의하고, 재료별 실패 방식은 사전 명세한다. 등장인물·협력·안전한 결말은 유지한다. 상세 범위는 [로드맵 §4](development-roadmap.md#4-동화-엔진과-가드레일)를 따른다.

### 제품 차별점과 개발 담당 확인 (10/28)

[1차 회의](../meetings/2026-10-28-2009-product-and-development.md)와 [2차 회의](../meetings/2026-10-28-2049-roles-and-integration.md), 사용자의 최종 확인을 반영했다.

- **제품의 핵심:** 동화의 교훈을 유지하면서 아이가 인과관계를 생각하고 창의적인 답을 내도록 돕는 경험, 익숙한 부모 목소리로 듣는 친밀감을 함께 강조한다. 부모 목소리는 핵심 경험으로 개발한다.
- **개발 담당 확정:** 현준님은 음성, 지호님은 동화 에이전트, 수찬님은 image to video·UI/UX·앱을 맡는다.
- **동화 진행 우선:** 초기 장면·배역은 사람이 설정하고, 아이 답을 판단·유도하는 에이전트를 먼저 만든다. 동화 전체를 자동 분석·구성하는 별도 에이전트는 후순위(TBD)다.
- **첫 편 변경 범위:** 집 재료 등 허용 요소를 바꾸고 등장인물·주요 사건·결말은 유지한다. 기존 아이 그림·캐릭터 개인화는 확장 백로그로 남긴다.
- **영상:** image to video를 개발 대상으로 채택했다. 대표 장면부터 검증하며 모델·제공사·길이·비용은 미정이다.
- **추가 제안:** 보유 음성·영상에서 참조 음성을 가져오는 방식과 Android 태블릿·폴더블 지원을 검토한다. 구현·권한·품질 확인 전 확정 기능이나 플랫폼 변경으로 취급하지 않는다.
- **협업:** 10/30(금) 중간 결과를 합쳐 보고 다음 범위를 조정한다. 상세 명세·연결 규격·검증 기준은 로드맵에서 관리한다.

### 낭독 생성 방식: 미리 생성 + 예상 밖 답만 실시간 (10/27)
- 정해진 대사(한 편 약 40줄)는 부모가 녹음한 직후 한 번에 생성해 저장한다. 실시간일 필요가 없다.
- 아이 답이 들어가는 대사는 **질문마다 예상 답(5~10개) 버전을 미리 생성**한다.
- 예상 밖 답("Ice cream!")만 그 자리에서 1~2문장 생성한다. 그림 생성(12~20초) 동안 끝난다.
- 안전장치: 녹음 시 본인이 동의 문장을 읽게 하고, 그 가족의 동화에만 쓰며, 목소리 삭제 기능을 둔다.

### 데모 기준 화면: `live.html` (10/30)
- 팀 결정(10/30 밤, 현준님 전달): 데모 화면은 `prototype/live.html`(수찬님 live book, `vision.server`의 실제 이야기·그림·음성 인식 사용)로 고정한다. 같은 날 잠시 지호님 `agent.html`을 기준으로 했다가 바꿨다. `agent.html`은 개발·시험 화면으로 둔다.
- 음성: 표지의 "Read by Dad"·설정의 "Reader … Change", 목소리가 없을 때 상단 "🎙 Add a parent's voice" → `voice.html?return=live.html` → 끝나면 live book으로 돌아온다. 답을 보내면 부모 목소리 맞장구, 3회 실패 보기도 읽는다. 부모는 영어 예문으로 한 번 녹음하고, 같은 목소리가 영어·한국어를 모두 읽는다.

### 배역 목소리와 데모 시나리오 (10/30)
- 내레이터와 돼지 삼형제는 부모 목소리(돼지는 표현 강도·속도를 높여 연기), 늑대는 공개 데이터셋(LibriTTS-R)의 다른 목소리로 읽는다. 4가지 방식을 듣고 비교한 결과다. 보호자가 원하면 모든 배역을 부모 목소리로 바꿀 수 있다.
- 데모는 **떨어져 있는 아빠**(훈련·파병·해외 근무)가 녹음해 둔 목소리로 아이가 이야기를 듣는 장면으로 한다.
- 지금 녹음할 수 없는 가족의 목소리는 보유한 영상·음성에서 구간을 골라 등록하는 방식을 제안한다. 상세 스펙과 안전장치는 [개발 로드맵 §5](development-roadmap.md#5-음성낭독-기능)를 따른다.
