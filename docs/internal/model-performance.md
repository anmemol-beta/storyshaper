# 대본의 성격·감정과 이미지·음성 연결

2026-10-31 사용자 후속 요청: 등장인물의 성격과 각 장면에서 겪는 감정을 이미지의 표정·몸짓, 음성의 말투, 실제 연기 녹음과 학습 자료에 연결한다.

## 공통 원본

- [한국어 대본](../../story_agent/story.ko.json)과 [영어 대본](../../story_agent/story.json)의 `characters`가 성격·말하는 방식·기존 외형 유지 규칙을 정한다.
- 각 발화의 `speakerId`, `tone`, `emotion`이 현재 순간의 연기 의도를 정한다. 이름표와 연기 지시는 실제 발화할 `text`에 섞지 않는다.
- [`performance.json`](../../story_agent/performance.json)은 성격별 음성 기본값, 말투·감정별 제어값, 감정별 얼굴·몸짓 지시를 정한다. [`performance.py`](../../story_agent/performance.py)가 이미지·음성·연습 화면에 같은 원본을 전달한다. 이 값은 사람이 작성한 표현 프리셋이며 학습된 가중치나 녹음의 감정 측정값이 아니다.
- [한국어 완성본](../../story_agent/scripts/three-little-pigs.ko.json)과 [영어 완성본](../../story_agent/scripts/three-little-pigs.en.json)의 28개 대체 장면은 `visualPerformance`와 낭독 순서대로 정렬된 `voiceDirections`를 포함한다. 마지막 음성 지시는 질문이 있는 장면의 `questionLine`에 해당한다.

## 이미지의 표정과 몸짓

실시간 `MuseImageProvider`와 정적 그림 제작 `media.generate_scenes`가 동일한 `visual_performance()`를 사용한다. 예를 들어 첫째 돼지는 짓기 전에는 들뜬 눈과 자세, 집이 흩어진 뒤에는 놀란 눈과 입을 표현한다. 막내는 신중한 작업 자세, 튼튼한 집 안에서는 안도하는 표정을 사용한다.

지시는 서버가 승인한 **현재 행동과 실제로 보일 배역**에서만 만든다. 집을 짓는 그림에 미래의 실패 반응이나 아직 보이지 않는 늑대를 넣지 않는다. 아이스크림 장면의 원인은 햇볕이며 늑대를 추가하지 않는다. 인물 외형·옷·재료·고정 사건은 기존 참조를 유지한다. 언어 변경만으로 같은 그림을 다시 생성하지 않도록 표현 지시는 언어에 독립적인 영어 원본으로 조립한다.

독립 이미지 검토는 기존 안전·재료·배역·행동에 더해 `expressionMatches`를 모두 확인한다. 표정·몸짓이 맞지 않거나 확인할 수 없으면 생성 성공으로 표시하지 않는다. 표현 정보의 리비전도 생성 캐시에 포함한다.

기존 객관식·오프라인 저장 그림은 바로 재사용하는 사용자 결정을 유지한다. 이번 변경은 새 생성·명시적 재제작 지시에 적용하며, 저장 그림을 자동으로 다시 만들지 않는다. 지시 전달·모형 검수 검증과 실제 생성 그림의 표현 품질은 구분한다.

```bash
python3 -m media.generate_scenes --dry-run --only house1/straw/build house1/icecream/melted house3/stone/stood
```

`--dry-run`은 지시만 출력하며 유료 생성은 하지 않는다.

## 음성의 성격과 말투

낭독 서버는 문장마다 `voice_direction()`을 호출해 `exaggeration`, `cfg_weight`, `tempo`를 실제 합성 설정에 넣는다. 내레이터는 차분하게, 첫째는 더 활기차게, 둘째는 익살스럽게, 막내는 신중하게, 늑대는 익살스러운 다른 배역으로 읽도록 기본값을 구분한다. 같은 인물도 놀람·안도·기쁨에 따라 강도와 속도가 달라진다.

기존 부모·기본 배역의 참조 음성 선택은 유지한다. 말투·감정·성격·리비전이 음성 캐시에 포함되어 같은 문장이라도 이전 표현의 음성을 잘못 재사용하지 않는다. 음높이만 바꿔 배역 연기를 완성한 것으로 취급하지 않는다. 기기 기본 음성 대체는 기존 가용성 정책을 따르며 Chatterbox의 연기 품질을 보장하지 않는다.

공식 Chatterbox의 표현 제어는 강도·참조 음성 등의 연속 제어다. 특정 감정 이름을 입력하면 그 감정을 반드시 재현하는 기능으로 해석하지 않는다. 실제 자연스러움과 감정 구분은 들어 보고 검수해야 한다.

## 실제 연기 녹음과 학습 자료

부모 목소리 등록 화면에서 추가 학습으로 이동하거나 [`voice-train.html`](../../prototype/voice-train.html)을 연다. 기존에 선택한 저장 목소리가 필요하다.

1. **동화 배역** 모드에서 언어·등장인물을 고른다. 실제 대본의 성격, 말하는 방식, 현재 감정과 읽을 문장을 보여 준다. 한·영 각각 98개 고유 발화·질문을 제공하며, 기존 일반 영어 연습 100문장도 별도로 유지한다.
2. 제시된 감정으로 읽고 녹음한다. 서버는 문장 ID와 대본 리비전을 원본에서 확인해 의도한 성격·감정 정보를 연결한다. 클라이언트가 임의로 보낸 감정 라벨을 학습 정답으로 사용하지 않는다.
3. 녹음을 끝까지 들어 보고 배역·감정이 맞는지 확인한다. 자동 전사와 대본의 일치도도 별도로 확인한다. 원하는 감정을 적어 둔 사실과 실제로 그 감정을 표현한 녹음은 구분한다.
4. 실제 WAV가 있고, 현재 대본과 일치하고, 전사가 기준을 통과하고, 연기를 확인한 녹음만 같은 목소리·배역·언어·선택 감정의 데이터로 내보낸다. 대본 변경·전사 수정 뒤에는 기존 확인을 재사용하지 않는다.

예시: 확인한 첫째 돼지의 들뜬 영어 연기만 학습 자료로 준비한다.

```bash
voice/.venv-chatterbox/bin/python -m narration.finetune --voice <voice-id> --language en --speaker pig1 --emotion excited --performance-only --export-only
```

산출물은 `wavs/`, 일치 전사 `metadata.csv`, 의도한 연기와 검토 기록 `performance.jsonl`, 배역·언어·감정 범위 `dataset.json`이다. 없는 녹음이나 합성 샘플을 실제 학습 녹음으로 만들지 않는다.

기존 영어 LoRA 학습 런타임을 설치한 뒤 `--export-only`를 빼면 확인된 실제 녹음으로 추가 학습한다. 현재 kit는 텍스트·음성 쌍을 학습하며 감정 라벨을 새로운 토큰으로 소비하지 않는다. 따라서 특정 배역·감정의 데이터로 제한한 학습 범위를 기록하고, 해당 범위의 영어 문장에서만 병합 모델을 사용한다. 다른 배역·감정은 기본 모델로 읽는다. 한국어 연기 녹음은 수집·내보내기를 지원하지만 현 영어 어댑터에 섞어 학습·적용하지 않는다.

이번 확인 시점에는 연기 학습용 클립이 0개이고 추가 학습 kit와 별도 학습 환경도 설치되어 있지 않다. 실제 가중치 추가 학습은 수행하지 않았다. 이미지도 가중치를 새로 학습한 것으로 표시하지 않으며 대본 지시·참조·검수로 연결했다.

## 이번 검증

- 전체 Python **318/318**, 화면·낭독·연습 Node **132/132** 통과. 이미지 표현 지시·검수 실패 차단, 실제 합성 함수의 제어 인자와 tempo 전달, 캐시 분리, 실제 WAV 선별·리비전·전사·청취 확인, 배역·감정 어댑터 범위, 목소리 삭제 시 파생 데이터 정리를 확인했다.
- 실행 중인 8100 서버에서 영어·한국어 카탈로그가 각각 98개이며 모든 배역의 성격·연기 지시가 있음을 확인했다. 합성하지 않는 `peek` 요청에서 같은 첫째 돼지 문장의 들뜸은 강도 0.85·속도 1.1, 안도는 강도 0.63·속도 1.008로 구분되고 음성 캐시도 달랐다. 이 수치는 작성한 프리셋의 전달 결과이며 자연스러움 평가 점수가 아니다.
- 정적 생성의 대표 세 장면은 `--dry-run`으로 확인했고, 한·영 완성본 28장면이 현재 공통 표현 계획과 일치했다. 실제 Chrome에서 새 배역 연습 화면과 목소리 선택이 필요한 경우의 안내를 확인했다.
- 앱 8000과 소유 음성 서비스 8100을 재시작해 변경을 적용했다. 실제 이미지 생성·음성 합성·가중치 학습·마이크 녹음은 이번 검증에서 실행하지 않았다.
