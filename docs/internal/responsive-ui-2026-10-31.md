# 화면 비율별 독서 UI 수정과 검증 — 2026-10-31

사용자 요청: 화면 비율 변경 시 창이 닫힌 것처럼 보이는 문제를 수정하고 각 비율의 UI/UX를 최적화한다. 로드맵 단계 4·§7의 독서 UI 범위이며 이야기·이미지·음성 처리 규칙은 이번에 변경하지 않았다.

## 재현과 원인

기본 앱은 `http://127.0.0.1:8000/` → `prototype/index.html`이다. `live.html`은 동일 HTML을 유지하고 진단용 `agent.html`은 별도다.

Chrome 반응형 모드 `844×390`에서 다음 명령으로 재현했다.

```javascript
JSON.stringify({
  viewport: [innerWidth, innerHeight],
  bookWidth: document.querySelector('#book').getBoundingClientRect().width,
  align: getComputedStyle(document.querySelector('#book')).alignSelf
})
// 수정 전: {"viewport":[844,390],"bookWidth":2,"align":"center"}
```

공유 `style.css`의 이전 가로 배치가 `.book`에 `align-self:center`를 남겼다. 새 독서 화면은 세로 flex 부모와 inline-size containment를 사용해 가로 폭이 사라졌다. 창을 닫는 JavaScript가 실행된 현상이 아니다. `live-book.css`를 `.reader-app`으로 구분하고 폭·정렬·grid 위치를 명시했다. 문서 전체의 고정 높이·스크롤 차단도 제거했다. 수정 후 같은 크기의 그림책 폭은 **810px**, 그림 높이는 **278px**다.

## 변경한 배치

- 좁은 화면: 그림 위·본문 아래. 높이가 부족하면 페이지 전체를 스크롤한다. 본문과 조작이 별도 스크롤 상자 안에서 0px로 줄어들지 않는다.
- 폭 600px 이상·비율 4:3 이상 또는 폭 1180px 이상: 그림 왼쪽·본문 오른쪽. 긴 본문을 읽을 때 그림이 함께 보이도록 고정하며 최대 앱 폭은 1440px다.
- 그림은 자르지 않고 맞춘다. 본문은 18~24px, 입력 글자는 16px 이상이며 일반 버튼·설정은 최소 44px다. 마이크는 오른쪽, 객관식은 80px 이상을 유지한다. 좁은 360px 이하에서는 객관식을 세로로 배치한다.
- 진단 화면은 1000px 이하에서 검사 패널을 본문 아래로 옮기고, 헤더·세션·답변 버튼을 줄바꿈한다. 진단 화면 객관식은 72px 이상이다.

검사 기준은 그림책 폭 유지, 그림·본문 높이 유지, 가로 넘침 없음, 표시 중인 조작이 화면 밖이나 잘리는 부모 영역에 숨지 않음, 터치 높이 44px 이상이다. 여러 번 비율을 바꾼 뒤 입력한 `화면 회전 유지 확인`과 현재 질문이 보존됨을 확인했다. 좁은 화면에서 마이크가 카메라 오른쪽에 있음도 확인했다. 실제 마이크·카메라 권한을 요청하지 않았다.

진단 화면은 카메라·마이크·인식 취소·제출 버튼을 모두 보여 준 배치 fixture에서 320×568, 500×700, 768×1024, 1000×700을 검사해 모두 통과했다.

반복 검사: [reader-layout-probe.js](../../tests/reader-layout-probe.js)를 DevTools Console에 붙여 넣고 `JSON.stringify(inspectReaderLayout())`를 실행한다. 원래 문제에서는 `pass:false`, 수정 후에는 `pass:true`를 반환한다. 자동 기능 회귀 검증은 `node --test tests/*.test.cjs`로 **78/78 통과**, 문법 검사와 `git diff --check`도 통과했다.

## 검증 한계

IAB 브라우저 연결 호스트가 없어 CUA의 네이티브 Chrome 제어로 검사했다. CSS·HTML 변경이므로 Python 서버·유료 이미지 생성 테스트를 다시 실행하지 않았다. 기본 오프라인 세션과 모델을 호출하지 않는 AI 시작 상태로 레이아웃을 검사했다. Safari·실제 모바일 키보드·노치·폴드 힌지/반접힘·실제 기기의 음성/카메라 동작은 별도 검증이 필요하다. 기존 데모의 힌지 배치를 새 독서 화면의 검증 완료로 취급하지 않는다.
