# StoryShaper — 부모 페르소나 기반 제품 방향 정의

> **문서 성격:** 해커톤용 경량 Product Brief (v0.2 / 2026-10-27)  
> **독자:** 디자인·기획·개발 담당자 모두  
> **목적:** 이미 정해진 개발 순서와 구현 방식을 다시 쓰지 않고, **누구를 위해 무엇을 만드는지**에 합의하기  
> **핵심 구조:** 육아 중인 부모 페르소나 → 아이의 상황별 반응 유형 → 원하는 경험 → 최소 제품 요구사항  
> **상태:** 팀 논의를 위한 초안. 연령·사용 시간·아이의 반응 유형은  
> **사용자 조사 결과가 아닌 가설**임. `docs/internal/plan.md`의 결정 사항과 미결정 사항을 구분하여 반영함.

## 0. 먼저 합의할 한 문장

**StoryShaper는 부모와 아이가 옆에 앉아 함께 이야기를 읽고, 아이의 말이 실제 그림과 이야기의 다음 장면에 반영되는 인터랙티브 동화책이다.**

- 우리가 파는 것은 AI 모델이나 음성 인터페이스가 아니라 **함께 이야기를 만드는 5~10분의 시간**이다. *(시간은 초기 가설)*
- **주 사용 장면은 공동 읽기(Co-reading)**다. 아이 혼자 조작하는 제품이나 부모만 쓰는 관리자 도구가 아니다.
- 부모가 함께 읽어줄 수 없는 날을 위한 **목소리 기반 보조 경험**은 중요하지만, 공동 읽기를 대체하는 것이 1차 목표는 아니다.
- 성공 장면: 아이가 “종이로 집을 지었어!”라고 말하자 그림에 종이집이 나타나고, 부모와 아이가 함께 보고 웃으며 다음 이야기를 이어간다.

## 1. 페르소나 (실제 인터뷰 전의 가설)

### P0 · 핵심 페르소나 — “하루가 바빠도 아이와 잠깐은 같이 읽고 싶은 엄마·아빠”

| 항목 | 정의 |
|---|---|
| 누구 | 미취학 자녀를 돌보는 부모. **아이 연령 4~6세는 초기 가설** |
| 상황 | 퇴근 후/저녁/잠들기 전, 에너지는 부족하지만 아이와 의미 있는 시간을 보내고 싶음 |
| 현재 문제 | 책을 읽어주려면 부모가 계속 내용을 이끌어야 하고, 아이가 금세 다른 자극을 찾기도 함 |
| 진짜 바람 | 긴 준비 없이 함께 웃고 이야기하며 **아이가 상상한 것을 존중받는 경험** |
| 사용 환경 | 부모와 아이가 **하나의 휴대폰·태블릿 화면을 나란히 봄** |
| 성공의 순간 | 아이가 먼저 아이디어를 말하고, 그림이 달라지는 모습을 부모와 함께 확인함 |
| 피하고 싶은 일 | 복잡한 가입·설정, 기술 설명, 긴 대기, 갑작스러운 무서운 장면, 계속 화면을 만지게 하는 조작 |

**Job to be done:** “아이가 책을 읽자고 할 때, 준비에 시간을 쓰지 않고 바로 옆에 앉아 상상력을 주고받고 싶다.”

### P1 · 보조 페르소나 — “매일 직접 책을 읽어줄 수는 없지만 정서적 연결을 남기고 싶은 부모”

| 항목 | 정의 |
|---|---|
| 누구 | 야근·교대근무·출장 등으로 읽어주기 시간을 자주 놓치는 부모 |
| 상황 | 다른 양육자가 아이 옆에 있거나, 부모가 잠시 함께하지 못하는 저녁 |
| 진짜 바람 | 부모가 자리에 없어도 **익숙하고 편안한 이야기 경험** 제공 |
| 주의점 | 부모 목소리 재현은 강한 감성 요소이지만, 녹음·복제 동의와 삭제 통제가 선행되어야 함 |
| 우선순위 | **P0를 해치지 않는 범위에서 확장**. 목소리 복제가 없더라도 핵심 이야기 경험은 성립해야 함 |

**Job to be done:** “내가 직접 읽어줄 수 없는 날에도 아이가 낯설지 않은 방식으로 이야기를 즐기면 좋겠다.”

### P2 · 확장 페르소나 — “집에서 쓰는 언어가 여러 개인 부모”

| 항목 | 정의 |
|---|---|
| 누구 | 다문화·다언어 가정 등에서 아이와 언어를 자연스럽게 나누고 싶은 부모 |
| 상황 | 부모와 아이가 더 편안한 언어가 서로 다르거나, 두 언어를 함께 접하고 싶음 |
| 진짜 바람 | 언어 시험 같은 부담 없이 **아이의 말과 부모의 언어가 존중되는 경험** |
| 주의점 | 번역의 정확성, 문화적 맥락, 음성 인식 품질은 별도로 검증 필요 |
| 우선순위 | **후속 확장 가설**. 해커톤에서 다국어 지원을 무리하게 약속하지 않음 |

**Job to be done:** “우리 집에서 편한 언어로도 아이와 자연스럽게 이야기를 나누고 싶다.”

**우선순위 선언:** 해커톤의 핵심 판단 기준은 **P0가 만족하는가?**이며, P1·P2는 방향을 잃지 않게 해주는 확장 축이다.

## 2. 아이 반응 유형 — 부모 페르소나에 겹쳐서 보는 **상황별 케이스**

> **팀에서 제안한 원문 유형:** “말잘듣는 아이 / 말 많은 아이 / 땡깡부리는 아이 / 수동적인 아이 / 결정장애 아이”.  
> 이 표현은 회의에서 나온 **테스트 케이스 별칭**으로 보존한다. 제품 화면·로그·문서의 공식 명칭에서는 아이를 성격이나 능력으로 고정 평가하지 않도록 아래와 같이 바꾼다. **같은 아이도 피곤함, 낯섦, 이야기 내용에 따라 하루에 여러 유형을 오갈 수 있다.** 의료적·발달적 진단 분류가 아니다.

| ID | 회의 때 부른 유형 | 문서용 행동 상황 | 아이가 보일 수 있는 반응 (가상 예시) | 부모가 바라는 경험 | 제품이 지켜야 할 반응 원칙 |
|---|---|---|---|---|---|
| **C1** | 말잘듣는 아이 | **질문에 바로 응답하는 경우** | “종이!”라고 짧고 명확하게 대답 | 내 말이 곧바로 이야기로 이어지는 뿌듯함 | 불필요한 확인 질문 없이 **그 답을 그림·대사에 반영** |
| **C2** | 말 많은 아이 | **긴 설명·끼어들기가 많은 경우** | “종이인데 파란색이고, 지붕엔 별이 있어!” | 말이 많아도 아이의 창의적 생각을 무시하지 않음 | 핵심 의도를 짧게 되짚고, **반영 가능한 요소부터 수용**. 현재 범위 밖이면 다정하게 다음 질문으로 연결 |
| **C3** | 땡깡부리는 아이 | **좌절·거부·강한 감정을 표현하는 경우** | “싫어! 늑대가 이겨야 해!” / “안 해!” | 갈등이 커지거나 부모가 아이를 달래느라 지치지 않음 | 감정을 혼내거나 논쟁하지 않음. **잠시 멈추기·건너뛰기·부모가 이어서 읽기** 선택권 제공. 위협적 전개는 부드럽게 제한 |
| **C4** | 수동적인 아이 | **응답 없이 듣기만 하는 경우** | 침묵, 시선만 그림에 둠 | 아이가 대답을 못 해도 이야기 시간이 어색하지 않음 | 재촉·카운트다운 없이 **기다림 → 쉬운 힌트 → 함께 고르기/이어 읽기**로 자연스럽게 진행 |
| **C5** | 결정장애 아이 | **선택을 어려워하거나 답을 바꾸는 경우** | “나무… 아니, 종이? 모르겠어.” | 정답 압박 없이 스스로 고를 수 있게 도움 | **2개 이하의 간단한 선택지·말로 힌트** 제공, 확정 전 답 변경 허용, 실패로 평가하지 않음 |

### 아이 반응 5가지에 대한 데모 수준의 최소 기대

- **C1 정상 경로:** 아이의 답 **한 번**으로 해당 소재가 다음 그림과 이야기에서 드러난다. *가장 먼저 완성할 기준 경로*.
- **C2 긴 답:** 말이 길더라도 “틀렸어/그건 안 돼”로 자르지 않고 핵심 소재 1개 이상을 이야기로 가져온다. **모든 세부 묘사를 무조건 반영해야 한다는 뜻은 아님**.
- **C3 거부·감정:** 아이가 답하지 않거나 강하게 거부해도 무한 반복 질문을 하지 않고, **동화를 멈추거나 보호자가 이어갈 수 있다**. 보호자와 함께 다시 시작하기 쉽다.
- **C4 침묵:** “말하지 않아도 괜찮아”라는 경험을 유지하며 **힌트 / 부모 동행 / 다음 진행**의 탈출 경로를 보여준다.
- **C5 망설임:** 짧은 선택 힌트를 제공해 아이가 부담 없이 결정하거나 스스로 답을 바꿀 수 있다.

**핵심 원칙:** 모든 케이스의 성공은 ‘아이를 원하는 대로 행동하게 만들기’가 아니라, **부모와 아이가 상처받지 않고 함께 읽는 흐름을 이어가는 것**이다. 부모와 아이를 별도 화면으로 분리할 필요는 없다.

**범위 판단:** 해커톤에서는 **C1 필수 + C3/C4/C5의 최소 복구 흐름**을 우선 추천하고, C2의 풍부한 장문 이해는 가능한 범위까지만 시연한다. 다섯 유형을 각각 별도 엔진으로 만드는 것은 목표가 아니다.

## 3. 페르소나가 원하는 경험 (Experience Goals)

| ID | 부모·아이가 원하는 경험 | 주 페르소나 | 중요도 | 경험이 성공했다는 신호 |
|---|---|---|---|---|
| **E-01** | **바로 시작한다.** 별도 설명서 없이 동화책 한 권을 펼치는 느낌 | P0 | 핵심 | 부모가 시연 설명 없이 첫 장면을 시작한다 |
| **E-02** | **함께 본다.** 한 화면에서 그림·이야기·질문을 공유 | P0 | 핵심 | 부모와 아이가 같은 장면을 보며 대화한다 |
| **E-03** | **말로 참여한다.** 글을 읽거나 복잡한 메뉴를 누를 필요가 없다 | P0 | 핵심 | 아이가 자연스럽게 자신의 아이디어를 말한다 |
| **E-04** | **내 말이 반영된다.** 정답 맞히기가 아니라, 아이디어가 장면을 바꾼다 | P0 | **차별점** | 말한 소재가 바뀐 **그림과 이야기**에서 확인된다 |
| **E-05** | **기다리는 동안에도 이야기가 이어진다.** 생성 대기가 몰입을 깨지 않는다 | P0 | 핵심 | 기다림 중에도 불안·멈춤·오작동처럼 느껴지지 않는다 |
| **E-06** | **틀려도 괜찮다.** 엉뚱한 대답이 안전하고 다정하게 이야기로 연결된다 | P0 + C1~C5 | 핵심 | 아이가 혼나거나 정답을 강요받지 않고 다시 말한다 |
| **E-07** | **잠자리에도 어울린다.** 과한 자극 없이 눈이 편하고 포근하다 | P0 | 중요 | 밤에도 읽기 편하고 UI가 그림책을 압도하지 않는다 |
| E-08 | **익숙한 목소리로 듣는다.** 부모가 부재한 날에도 친근함을 느낀다 | P1 | 선택/확장 | 부모가 명시적으로 선택한 음성으로 읽어준다 |
| E-09 | **우리 집 언어로 읽는다.** 가정의 언어 선택을 존중한다 | P2 | 후속 | 선택한 언어로 아이와 자연스럽게 상호작용한다 |
| **E-10** | **아이의 반응 속도를 존중한다.** 빠른 답, 긴 답, 거부, 침묵, 망설임 모두에서 함께 읽기를 이어간다 | P0 + C1~C5 | **핵심** | 부모가 대답을 강요하거나 앱 오류를 수습할 필요가 없다 |

### 가장 중요한 세 가지 경험

1. **한 화면에서 함께 읽고 말한다** — 단독 학습 앱이나 화면 분리형 서비스와 다름.
2. **아이의 말이 그림을 바꾼다** — 단순 챗봇·오디오북과 다른 StoryShaper의 고유 가치.
3. **부모에게 일을 더 만들지 않는다** — 설정·통제·대기는 최소화하고, 부모는 아이와 이야기를 나누는 데 집중.

## 4. 최소 제품 요구사항 (상세 기능 명세 아님)

> 아래는 *제품이 반드시 제공해야 할 성질*이다. 구현 방식, 모델, API 연결 순서, 담당자, 스프린트 계획은 **기존 개발 계획**에서 관리한다.

| ID | 제품 요구사항 | 연결된 경험 | 해커톤 우선순위 |
|---|---|---|---|
| **PR-01** | **공동 읽기 우선:** 아이와 부모가 동일한 이야기 화면을 공유하며, UI보다 원화·문장이 주인공이어야 함 | E-01, E-02 | **필수** |
| **PR-02** | **음성 참여:** 이야기의 적절한 시점에 아이가 말할 차례를 알아차리고, 음성으로 의견을 낼 수 있어야 함 | E-03 | **필수** |
| **PR-03** | **실제 반영:** 아이의 말이 단순 말풍선에만 남는 것이 아니라 다음 장면의 **그림과 이야기**에 의미 있게 반영되어야 함 | E-04 | **필수/제품 정체성** |
| **PR-04** | **흐름 유지:** 그림 생성·응답이 지연되더라도 부모와 아이는 현재 무슨 일이 일어나는지 이해할 수 있고 이야기가 끊기지 않아야 함 | E-05 | **필수** |
| **PR-05** | **다정하고 안전한 반응:** 위험하거나 엉뚱한 답에도 아동 적합성을 지키면서 무안 주지 않는 반응이 필요함 | E-06 | **필수** |
| **PR-06** | **편안한 그림책 UI:** 수채화·파스텔 디자인, Light/Dark/Auto 테마 및 이야기 중심 화면 | E-01, E-02, E-07 | **필수** |
| **PR-07** | **부모가 통제 가능:** 언제든 재생·멈춤·처음부터 보기 같은 기본적인 조정이 가능하고, 아이와 함께 보는 화면을 방해하지 않아야 함 | E-01, E-05 | 중요 |
| **PR-08** | **음성·아동 데이터 보호:** 녹음이나 부모 목소리 복제 시 사전 안내·동의·삭제 통제 필요. 불필요한 장기 보관을 기본값으로 두지 않음 | E-03, E-08 | **해당 기능 사용 시 필수** |
| PR-09 | **부모 목소리 읽어주기:** 부모가 원할 때에만 익숙한 목소리로 읽어주는 선택지를 제공 | E-08 | 선택/확장 |
| PR-10 | **가정별 언어 선택:** 부모와 아이가 편한 언어를 선택할 수 있는 경험으로 확장 | E-09 | 후속 |
| **PR-11** | **다양한 아이 반응 포용:** C1~C5 중 어느 상황에서도 다정한 응답 또는 자연스러운 멈춤/도움 흐름이 있어야 하며, 강요·채점·무한 질문 루프를 피한다 | E-06, E-10 | **필수 원칙** (구현은 단계적) |

**아무리 러프한 해커톤이라도 `PR-03`이 빠지면 StoryShaper가 아니라 ‘말 걸 수 있는 동화책’이 된다.** 이 요구사항을 가장 먼저 지켜야 한다. 다만 **`PR-11`을 놓치면 일부 아이에게는 말을 강요하는 동화책**이 될 수 있으므로 정상 흐름과 함께 최소 예외 대응은 확보한다.

### 의도적으로 이번 문서에 넣지 않는 것

- 프레임워크·API 스펙·서버 구조·DB 스키마·상태 머신 상세 설계
- 개발 태스크 순서·담당자 배분·예상 공수·테스트 케이스 나열
- 별도 **아이 전용 / 부모 전용 화면** 설계 또는 거대한 보호자 대시보드
- 장기 기능인 그림 촬영·캐릭터 추가·복잡한 개인화/학습 성적 추적·아이 행동유형 자동 분류/프로파일링

## 5. 팀이 공유할 대표 사용 장면 (1분 설명용)

**저녁 8시, 부모와 5세 아이가 소파에 나란히 앉는다.** *(시간·나이는 가상의 예시)*

1. 부모가 StoryShaper의 **아기돼지 삼형제**를 펼친다. 화면에는 큰 수채화 그림과 짧은 문장만 보인다.
2. 동화가 “첫째 돼지는 무엇으로 집을 만들었을까?”라고 묻는다. 아이는 **“종이!”**라고 말한다.
3. 시스템이 아이의 답을 다정하게 받아들이고, 종이집이 그려진 장면을 보여준다. 생성하는 동안에도 이야기의 흐름은 유지된다.
4. 부모가 “우와, 네가 말한 종이집이 생겼네!”라고 반응한다. 아이는 다음 질문에도 자기 생각을 말한다. **만약 아이가 머뭇거리거나 말하지 않으면**, 부모는 화면의 가벼운 힌트를 통해 함께 고르고 계속 읽을 수 있다.
5. 다 읽고 나면 부모와 아이에게는 **‘AI를 조작했다’가 아니라 ‘같이 이야기를 만들었다’**는 기억이 남는다.

**이번 데모를 보고 평가할 질문:** “아이의 한마디가 책을 바꿨다는 사실을 10초 안에 알아볼 수 있는가?”

## 6. 화면 디자인에 대한 제품 수준의 원칙

- **공동 화면 1개:** 기존 UI A안 **‘펼친 그림책’**을 기본으로 하고, B/C안은 표현 방식의 대안이지 별도의 사용자 유형이 아니다.
- **Light = 햇살 드는 종이책**, **Dark = 밤에 읽는 잠자리 책**. 그림 원본의 색은 유지하고 주변 UI를 테마화한다.
- **큰 그림 > 짧은 이야기 > 말할 차례 안내** 순서. 개발용 수치와 시스템 단계는 주인공이 아니다.
- **부모 조작은 작고 가까이:** 부모가 아이 옆에서 간단하게 조정할 수 있어야 하되, 사용 중 팝업이 몰입을 깨지 않도록 한다.
- **정답 찾기보다 상상력:** 분기가 고정되어 있더라도 아이에게는 자신의 생각이 존중되고 실제로 반영되는 경험이어야 한다.
- **아이를 유형화하는 UI 금지:** C1~C5는 개발·시연 준비용 행동 시나리오이지, 아이에게 붙이는 상태 배지나 부모가 선택하는 성격 진단이 아니다.

상세 HEX/반응형/컴포넌트는 기존 [`StoryShaper_UI_Design_3_Concepts.md`](../StoryShaper_UI_Design_3_Concepts.md) 참조. 문서 경로는 실제 저장 위치에 맞게 수정.

## 7. 현재 GitHub와의 연결 (2026-10-27 확인)

- 저장소: **https://github.com/anmemol-beta/storyshaper** (기본 브랜치 `main`, 확인 당시 public)
- `main`의 `prototype/`에는 **아기돼지 삼형제** 시나리오와 이미지 기반 클릭형 프로토타입이 있다.
- **PR #2 (`ui_mvp` → `main`)는 확인 당시 열린 상태**였다. 공동 화면, A안 디자인, Light/Dark/Auto, 반응형 UI 및 이야기 상태 표현을 다룬다. **아직 `main`에 병합된 것으로 간주하면 안 된다.**
- PR #2 기준으로도 **실제 마이크 입력 → 음성 인식 → 이야기 생성 → 그림 재생성**의 라이브 연결은 아직 끝나지 않았고, 마이크 데모는 미리 정한 첫 번째 답변을 반환하는 형태라고 README에 명시되어 있다.
- 저장소 README는 이야기 1턴에서 음성 인식 약 3초, 글 생성 약 3~7초, 그림 갱신 약 12~20초를 **개발 실험 관측치**로 제시한다. 이는 서비스 성능 보장치가 아니다. 그래서 **E-05 / PR-04**가 중요하다.
- 저장소 내 `voice/`에 음성 샘플 파일이 포함되어 있으므로, **부모 실제 음성을 포함하는 경우 공개 저장소에 올릴 데이터 범위와 동의 여부**를 반드시 확인한다. 해당 음성의 권리·동의 상태는 이 문서에서 확인하지 못했다.

**해석:** UI 방향은 상당 부분 정리되어 있으며, 다음 검토는 **화면을 얼마나 더 만들지**가 아니라 **현재 UI가 P0의 E-02/E-03/E-04를 실제 경험으로 보여주는지**에 집중하는 것이 좋다.

## 9. 개발 담당자에게 넘길 때 남길 결정 질문 4개

1. **핵심 시연 대상:** 부모와 아이가 **함께 읽는 경험**을 해커톤의 공식 주요 시나리오로 합의할까? → **추천: 예**
2. **핵심 차별점:** ‘아이가 말한 것이 그림에 즉시(또는 짧은 기다림 후) 반영됨’을 다른 기능보다 우선할까? → **추천: 예**
3. **부모 목소리:** 실제 보이스 클로닝을 MVP 성공 필수조건으로 볼까, 추가 감동 요소로 볼까? → **추천: 추가 감동 요소**
4. **범위:** 다국어·사진 속 그림 반영·아이 개인화 등은 제출 이후로 미룰까? → **추천: 예**

**팀에 전달할 문장:** “우리는 부모를 대신하는 AI가 아니라, 부모와 아이가 함께 상상하고 이야기를 나누도록 도와주는 그림책을 만든다.”
