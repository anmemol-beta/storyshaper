# StoryShaper 개발 기능과 개발 순서

작성: 2026-10-27 KST. 갱신: 2026-10-31 KST(아이용 기본 화면·그림 표시 전 진행 차단·첫 실패 후 키워드 전용 입력 반영). 상태: 사용자 요구사항과 회의 결과를 반영한 개발 계획. §12의 기능 담당은 확정했고 세부 연결 규격은 제안이다. 기능 구현이나 배포 완료를 뜻하지 않는다.

## 1. 목표와 범위

아이가 말하거나 직접 그린 그림으로 동화의 일부를 바꾸고, 부모 목소리로 이야기를 들으며, 원래 동화의 주요 사건과 교훈을 따라 결말까지 도달하는 iPad용 인터랙티브 그림책을 만든다.

- **사용자 요구:** iPad 앱 배포, 브라우저·iPad 마이크, 부모 목소리와 캐릭터별 음성, 동화 3편 이상, 이미지 변환, 짧은 영상, 이야기 가드레일과 자연스러운 재시도, 아이 그림 활용, 다국어, 자연스러운 낭독, 독서 UI와 보호자 설정, 데모 영상.
- **개발 순서 제안:** 웹에서 한 편의 실제 사용 흐름 완성 → 부모 음성·독서 경험 안정화 → 동화 3편 → 그림·영상·다국어 확장 → iPad 앱 배포. iPad 호환성 확인과 배포 준비는 초기에 시작한다.
- **대상 연령:** 2026-10-29 사용자 확인으로 **4~7세**를 대상으로 한다. 이번 품질 개선에는 짧고 쉬운 말, 눈에 보이는 변화와 구체적인 질문을 반영한다. 연령별 어휘·문장 길이·질문 난이도의 세부 기준과 페르소나는 후속으로 다듬으며, 생성 결과의 자연스러움과 아동 이해도는 별도로 검증해야 한다.
- **미정:** 영어 외 첫 지원 언어, 추가 동화 2편, iPad 앱 구현 기술, 영상 생성 방식·제공사, 운영 서버와 예산, 실제 배포 일정.
- 기존 영어 우선 방침은 첫 동작 검증에 적용하고, 최종 제품에는 다국어를 포함한다. 다국어 준비를 위한 데이터 구조는 처음부터 둔다.
- 이 문서는 기능과 순서의 기준이다. [기획 메모](plan.md)의 문제 정의·모델 실험 기록은 참고하되, 이전의 단일 동화·확장 기능 범위는 이 계획으로 갱신한다.

숫자는 기본 의존 순서다. 0단계의 iPad 사전 검증, 1단계의 보호자 설정 골격, 5단계의 추가 동화 집필, 10단계의 데모 대본은 일찍 시작할 수 있다. 전체 확장이 끝나기 전에도 안정적인 기능 묶음으로 iPad 베타와 데모를 먼저 만들 수 있다. 개발 담당과 중간 통합 계획은 §12를 따르고, 세부 API 경계와 제출 범위는 추가 합의한다.

**2026-10-31 사용자 후속 요구 — 앱 형태로 실행:** Z Fold8에서 단순 브라우저 탭으로만 표시되어 주소창과 탭이 보인다는 점을 확인했다. 데모의 설치형 실행은 우선 Web App Manifest의 `standalone` 표시와 홈 화면 아이콘으로 검증한다. 이는 PWA 웹 앱이며 네이티브 APK/iPad 앱 완료가 아니다. 현재 `127.0.0.1:8000` 연결은 USB ADB reverse가 있어야 동작하는 개발 환경이므로 기기 단독 실행·배포 증거로 취급하지 않는다. 최종 앱은 서버 호스팅/인증·마이크/카메라 권한·앱 서명·실기기 검증을 선행해 단계 9에서 결정한다. iPad 목표는 유지하며 Android용 APK와 iPad용 빌드 기술은 아직 미정이다.

2026-10-28 회의와 사용자 확인에 따른 3인 개발 담당·통합 계획은 §12에 기록했다. 현준님은 음성, 지호님은 동화 에이전트, 수찬님은 image to video·UI/UX·앱을 맡는다. 제출에 포함할 세부 기능 범위는 검증 결과로 정한다.

### 중간에 확인할 결과물

| 결과물 | 포함할 범위 | 다음 확장으로 넘어가는 조건 |
| --- | --- | --- |
| **A. 실제 동작하는 첫 편** | 단계 0~2, 임시 기본 낭독, 입력·출력 가드레일, 재시도 | 정상·거절·오인식·생성 실패 경로가 모두 진행 가능 |
| **B. 사용할 수 있는 그림책** | 부모 목소리, 기본 배역 음성, 독서 UI, 보호자 설정, 동화 3편 | 부모 등록부터 아이 독서·이어 읽기까지 검증 |
| **C. 확장된 iPad 제품** | 아이 그림, 영상, 다국어, iPad 배포 | 선택한 배포 범위의 실기기·음성·영상 품질과 개인정보 처리 검증 |

대회용 첫 시연은 A 완성과 B의 부모 목소리 적용을 우선하는 제안이다. 3편·영상·다국어·iPad 정식 배포도 전체 백로그에 유지한다. 대회 제출 때 모두 넣을지는 남은 개발 시간과 검증 결과로 결정하며, 아직 완료 날짜를 확정하지 않는다.

## 4. 동화 엔진과 가드레일

### 대본 기반 이미지 표현·음성 제어·연기 학습 자료 — 2026-10-31 후속 요청

- **적용 단계:** 단계 3의 배역별 음성·추가 학습과 단계 6의 이미지 표현 입력을 기존 성격·감정 대본에 연결한다. 앞선 '줄별 감정 합성·성격에 따른 이미지 검수는 별도'에서 이번 구현 범위를 확장한다.
- **공통 표현 계획:** `story_agent/performance.py`·`performance.json`이 인물별 성격, 문장별 말투·감정, 얼굴·몸짓, 지원되는 합성 제어값을 조립한다. 모델 입력 완성본에도 장면별 `visualPerformance`와 낭독 순서의 `voiceDirections`를 포함한다. 프리셋을 학습된 가중치로 표시하지 않는다.
- **이미지:** 실시간·정적 생성 지시에 현재 장면의 표정·몸짓을 전달한다. 승인된 배역만 표현하고 집짓기 전에 실패 반응을 앞당기지 않는다. 독립 검토의 `expressionMatches`가 참이어야 통과하며 표현 리비전은 생성 캐시에 포함한다. 기존 객관식 저장 그림의 즉시 재사용은 유지하고 자동 재생성은 하지 않는다.
- **음성:** 인물·말투·감정별 `exaggeration`·`cfg_weight`·`tempo`를 실제 합성·후처리에 적용하고 음성 캐시를 구분한다. 기존 부모·기본 배역의 음색 선택은 유지하되 돼지 셋의 표현 강도·속도를 구분한다. 실제 감정 전달과 자연스러움은 청취 검수가 필요하다.
- **연기 녹음·학습:** 보호자 추가 학습 화면에서 한·영 대본의 배역·성격·감정 지시를 보고 녹음한다. 서버의 대본 ID·리비전과 일치하는 실제 WAV·전사, 사람이 확인한 연기만 같은 목소리·배역·언어·선택 감정의 자료로 내보낸다. 기존 일반 영어 연습은 유지한다. 학습 범위를 모델에 보존해 다른 배역·감정에 해당 어댑터를 적용하지 않는다. 한국어는 현재 수집·내보내기까지만 지원하고 영어 어댑터에 섞지 않는다.
- **확인 범위:** 실제 연기 녹음은 현재 0개이며 별도 학습 환경도 없다. 따라서 실제 가중치 학습 완료나 특정 감정의 생성 품질을 주장하지 않는다. 모델이 지원하는 생성 조건 전달과 실제 녹음 수집·선별·학습 연결을 구현하고 모형·HTTP·UI로 검증한다. 상세 규격·실행법·공식 근거는 [표현·학습 안내](model-performance.md)를 따른다.

### 4~7세 대상 품질 개선 사례 — 2026-10-29

사용자가 실제 모델 시험 결과에서 다음 개선 필요성을 확인하고 개선 범위를 결정했다. 사례와 기대 방향은 [시험 가이드의 품질 피드백](story-agent.md#품질-피드백--2026-10-29)에 기록한다. 아래는 승인된 요구사항이며 구현·품질 검증 완료를 뜻하지 않는다.

- **재료 의미와 지원 범위 구분:** “비닐로 짓고 싶어!”를 비롯해 **낯선 재료 전반의 해석 범위**를 넓힌다. 비닐 하나를 별칭 목록에 추가하는 방식으로 한정하지 않는다. 아이가 말한 재료와 검증된 물성을 보존하고, 지원하기 어려운 재료라는 안내를 뜻을 알아듣지 못했다는 안내와 구분한다. 모든 재료의 수용을 보장하지는 않는다.
- **과정 관찰과 추론 지원:** 아이스크림집에 “더 커질 것 같아!”라고 예상하면 그 생각을 짧게 받아준 뒤, 말랑해짐·흘러내림처럼 관찰할 수 있는 변화를 설명하고 결과로 이어간다. **추가 응답 턴 없이 같은 응답 안에서 과정 → 결과 → 쉬운 질문**으로 진행한다. 집마다 재료 선택·예상·이유 설명의 세 지점과 총 9턴 흐름, 최종 사건과 안전한 결말은 유지한다. 비유는 이해를 돕는 데만 쓰고 잘못된 원인이나 새 사건을 만들지 않는다.
- **품질 검증:** 위 실제 문답을 비교 사례로 유지하고, 자연스러운 한국어·쉬운 표현·아이 답의 반영·결론 제시 시점을 평가한다. 상태 전이·안전성 테스트와 구분한다. 오프라인 재현은 실제 모델의 새 생성 품질 검증으로 취급하지 않는다.

### 낯선 재료의 검증과 보존 — 2026-10-29 확정 범위

- 해석 모델은 기존 재료 식별자 또는 `{source, labels: {en, ko}, behavior}` 형태의 재료 제안을 반환한다. `source`는 아이 원문에 실제로 나온 재료명이다. 서버가 스키마·문자열·원문 일치를 검증하며, 이름을 다른 재료로 바꾸거나 모델이 새 사건을 지정하게 하지 않는다.
- `behavior`는 `light_flexible / loose_pieces / edible / melts / rigid` 중 하나다. 서버가 각각 `blown_away / collapsed / eaten / melted / stood`라는 기존 다섯 결과로 연결한다. 얇게 걸치기·느슨하게 쌓기·단단히 붙이기 등 장면의 시공 조건을 함께 설명해 재료만 같으면 언제나 같은 일이 생긴다고 단정하지 않는다.
- 기존의 별도 출력 검토 단계에서 제안이 원문과 같은 재료를 뜻하는지, 한영 명칭이 같은 대상을 가리키는지, 물성·현실 가능성·아동 안전성과 사건이 맞는지도 검토한다. 스키마 검사를 통과한 제안을 곧바로 사실로 취급하지 않는다. 검토 실패는 상태를 확정하지 않는 모델·서비스 오류로 처리하며 아이 실패 횟수에 넣지 않는다.
- 첫 두 집의 `rigid` 재료, 마지막 집의 약한 재료처럼 고정 사건과 맞지 않으면 뜻을 인정한 뒤 다시 안내한다. 의미는 알지만 지원하기 어려운 답은 `unsupported_material`, 뜻이 모호한 답은 `unclear_answer`로 구분한다. 어느 경우든 첫 실패 직후 아래 터치 선택형 전환 규격을 적용한다.
- 검증된 새 재료는 해당 세션의 집 상태에 `material: "custom"`, `materialSpec`과 안정적인 `materialId`로 보관한다. 다음 질문·후속 장면·언어 전환·미디어 전달 데이터에도 같은 재료와 사건을 유지한다. 전역 재료 목록이나 별칭 사전에 자동 등록하지 않는다.
- 준비된 대체 대사에도 같은 과정 설명과 쉬운 질문을 적용한다. 실제 모델의 새 재료 해석·물성 검토·과정 설명 품질과 4~7세 이해도는 별도로 확인하고, 테스트 수와 실행 결과는 검증 뒤 시험 가이드에 기록한다. 실제 마이크·그림·영상·부모 목소리 통합의 남은 범위는 그대로다.

- 재료 선택에만 재료 목록·제안 규격을 보내며, 이후 질문에는 현재 재료와 질문 문맥을 사용한다. 생성·검토에는 확정된 전이 사실·필수 과정·안전한 결말을 보존하고 전체 이전 집 상태의 중복 전송을 줄인다. 예측 응답의 과정→결과·질문 지시는 해당 단계에만 추가한다. 재료 선택 후 대사는 건축·상황 설정까지만 보여 주고, 아이가 예상하기 전에 미래의 변화 과정을 서술하지 않도록 과정 데이터를 분리하고 생성·검토에서 확인한다.
- 같은 비닐·아이스크림 문답으로 기존 설정, 생성 추론만 낮춘 설정, 문맥까지 줄인 설정을 순서대로 비교한다. 실제 완료·검토 수용·재료명 보존·추가 턴 없음과 지연을 함께 기록하며, 실패한 응답을 빠른 성공으로 집계하지 않는다. 작은 표본의 결과를 평균 성능이나 아동 이해도 보장으로 해석하지 않는다. 실행·수치·한계는 [시험 가이드](story-agent.md)에서 관리한다.

### 선택적 독립 검토와 문맥 공유 — 2026-10-30 후속 구현 요청

- 사용자 요청으로 단계 1~2의 속도 최적화를 구현했다. 앱의 기본 `adaptive`는 등록 재료의 단순 선택과 관찰 과정→결과 순서가 확인되는 예상 응답을 **1호출 + 서버 검사**로 처리한다. 낯선 재료와 후속 장면, 복잡하거나 부정·추가 조건이 있는 답, 과정·재료 일관성을 로컬에서 확인하기 어려운 대사, 집 이동·결말은 **2호출 독립 검토**를 유지한다. 터치 선택은 0호출이다.
- 초안·독립 검토는 `low`를 유지한다. 기존 실측에서 `minimal` 검토가 잘못된 재료 대사를 통과시킨 기록을 반영하며, 모든 답에서 검토를 제거하지 않는다. 서버의 형식·재료·인과관계·상태 전이·첫 실패 터치 검사와 검증 후 미디어 전달은 유지한다. 빠른 경로의 의미 품질이 전체 독립 검토와 동등하게 입증된 것은 아니다.
- 재료 선택의 공통 건축 대사와 전이 사실을 한 번만 전송하며 단계별 과정 제한을 보존한다. Spark의 Responses JSON Schema 출력을 사용하고, `store:false`·8,192 토큰·30초·자동 재시도 없음은 유지한다. 안정된 문맥 뒤에 아이 답을 배치한다.
- 실시간 그림 생성은 `reasoning_strength:low`로 단일 정제 패스를 사용한다. 승인된 사실만 전달하고 기존의 별도 이미지 검수·세션/버전 바인딩·실패 시 대체 표시를 유지한다. 생성 자체와 이미지 검수는 여전히 별도 모델 요청이다.
- 설정·호출 수·추가 검토 사유와 비교용 `two_call`을 제공한다. 한영 준비 문답 9턴은 18→12호출, 고정 비닐·아이스크림 비교는 6→4호출로 오프라인 확인했다. 실제 Muse 지연·생성 품질·새 그림의 단일 패스 품질은 이번에 재측정하지 않았으며 사용자 시험이 남는다. [실행·비교·검증 기록](story-agent.md#선택적-독립-검토와-속도-최적화--2026-10-30).

### 검증 순서

`녹음/그림 → 입력 확인 → 안전성·장면 적합성 판정 → 변경값 제안 → 서버 검증 → 대사 검증 → 이미지/음성/영상 생성 → 결과 검증 → 표시·상태 확정`

- 판정은 `수용 / 뜻 확인 / 자연스러운 전환·재시도 / 처리 실패`로 구분한다. 음성 인식 실수와 안전성 거절을 같은 메시지로 처리하지 않는다.
- 성적 표현·노출 요구·혐오·괴롭힘·과도한 폭력·개인정보 요구를 사전에 제한한다. 사진·그림 입력과 생성 결과에도 기준을 적용한다.
- 인종·피부색 자체는 금지어로 두지 않는다. 비하·차별 의도와 장면에서 허용하는 외형 변경인지 각각 판단한다. 무해한 다양성 표현과 모욕적 요청을 구분한다.
- 엉뚱한 상상과 불가능한 요구를 구분한다. “아이스크림 집이 녹았네”처럼 안전하고 교훈에 맞게 수용할 수 있는 답은 살린다. 불가능한 물체는 안전한 대안으로 안내한다.
- 검증이 실패하거나 서비스를 사용할 수 없으면 검증 전 콘텐츠를 아이에게 노출하지 않고 기본 장면·선택지를 제공한다.

| 입력 예 | 처리 방향 | 아이에게 보여줄 응답 예 |
| --- | --- | --- |
| “종이로 집을 지을래” | 허용 장면에서 수용 | “좋아! 종이를 차곡차곡 접어 집을 만들어 보자.” |
| “sun으로 집을 지을래” | 불가능한 재료, 대안 제시 | “햇님은 너무 뜨거워서 만질 수 없네. 햇님처럼 노란 지붕은 어때?” |
| “신데렐라 옷 벗겨줘” | 노출 요청 차단, 안전한 변경 제안 | “신데렐라에게 멋진 새 옷을 골라 주자. 어떤 색이 좋을까?” |

“틀렸어”, “금지야”보다 짧은 이야기 속 이유와 가능한 대안을 함께 제시한다. 첫 실패부터 아래 기준으로 객관식 선택형으로 전환한다. Voice API가 제공하지 않는 인식 신뢰도 점수를 전제로 설계하지 않는다.

- 한 질문에서 답변 미수용 또는 음성 인식 실패 중 **먼저 발생한 첫 실패**가 전환 조건이다. 다른 종류의 실패가 더 발생할 때까지 기다리지 않는다.

- 실패 확인 직후 **같은 터치 화면에 보기를 바로 표시하고 누를 수 있는 상태**로 만든다. 별도의 ‘보기 열기’ 버튼, 추가 발화·재녹음, 낭독 완료나 이미지 생성을 기다리게 하지 않는다.
- 전환 안내 예: “이번에는 그림을 보고 골라 볼까? 마음에 드는 걸 톡 눌러 줘!” 화면 표시와 함께 짧게 안내해 아이가 바로 답을 누르도록 유도한다. 실패 횟수나 오답을 아이에게 강조하지 않는다.
- 아이가 보기를 **한 번 터치하면 해당 선택을 제출**한다. 서버가 현재 질문의 허용 선택인지 검증한다. 전환 후 같은 질문에서는 마이크·글·카메라를 숨기고 비활성화하며 선택지로만 답한다. 서버도 `choiceMode:true`에서 `choiceId` 없는 자유 답을 모델 호출·턴 집계 전에 거절한다. 로컬 음성 실패는 추가 빈 답 요청 없이 UI에서 잠근다.
- **이미지 생성 후속 전달:** 선택 항목의 식별자(`choiceId`)·표시 문구·선택값과 세션·장면·질문·버전 문맥을 연결해 보존한다. 서버가 확정한 재료명·`materialId`·`materialSpec` 등 해당 선택의 승인된 변경값을 `mediaPlan`에 연결해 추후 이미지 생성 쪽으로 전달한다. 실패한 발화나 클라이언트 임의 값으로 이미지를 생성하지 않고, 아이가 실제로 누른 선택과 같은 재료·사건을 사용한다. `selection` → `mediaPlan.selection` → 미디어 작업의 `spec.selection` 전달은 구현·HTTP 자동 검증했으며, 실제 이미지 생성 API 연결·생성 결과 검수는 후속이다.
- 선택이 승인되어도 다음 장면 그림이 실제 표시되기 전에는 모든 답 입력을 잠근다. 그림 표시 완료 후 새 질문에서 자유 입력을 다시 허용한다. 같은 질문의 화면 복귀·언어 전환·다시 듣기로 선택 전용 상태를 해제하지 않는다. 같은 발화 재처리·연속 터치는 중복 집계·중복 진행하지 않으며, 재시작하면 새 질문 상태로 시작한다.

**현재 구현:** 아이용 `index.html`은 첫 미수용 답·녹음/인식 실패 때 세 키워드만 표시한다. 서버의 `attempts`는 실제 제출된 미수용 답만 집계하며 로컬 보기 표시로 늘리지 않는다. 서버가 현재 세션·질문·버전과 보기 ID를 검증하고, 선택 전용 상태의 자유 입력을 거절한다. 새 그림 디코딩·화면 전환 뒤 다음 본문과 질문을 연다. 늦은 녹음·인식·이미지 결과는 재시작 뒤 새 화면에 적용하지 않는다. 실제 기기·실제 Muse 시험은 자동 테스트와 구분한다. ### 발달 단계별 참여 방식 — 2026-10-30 현준님 제안 (미확정)

대상 연령 4~7세(§1, 10/29 확정)는 유지한다. 질문에 답하지 못하는 아이를 "듣기만" 하게 두기보다, 같은 책에서 **질문의 난이도와 답하는 방법**을 발달 단계에 맞춰 바꾸자는 제안이다. 아래 연령 구분은 미국 CDC 발달 이정표(2022 개정)의 언어·인지 항목을 참고한 대략적인 기준이며, 아이마다 차이가 크고 실제 아동 관찰로 검증하지 않았다.

| 단계 | 대략 나이 | 아이가 할 수 있는 것 | 이 책에서의 참여 |
|---|---|---|---|
| 듣기 | 2~3세 (대상 밖, 확장) | 그림 가리키기·이름 말하기. 원인과 결과 예측은 아직 어려움 | 부모 목소리로 듣기, "같이 후~ 불어 볼까?", 반복 구절 따라 하기, 그림 짚기. 선택은 보호자가 대신 |
| 고르기 | 3~4세 | 둘 중 고르기, 그림 속 행동 말하기 | 처음부터 그림 카드 2~3장. 말로 하거나 눌러서 고름. 예측은 예/아니오 |
| **대화 (기본)** | **4~6세** | 책 내용에 대한 간단한 질문에 답하기, "다음에 어떻게 될까" 예측, 쉬운 원인과 결과 | 현재 흐름: 자유 답변, 예측, 이유 묻기 |
| 만들기 | 6~7세 | 사건 두 개 이상으로 이야기 만들기, 이유 설명, 대안 내기 | 재료 외에 행동까지 바꾸기(지호님 10/30 아이디어, 제출 후 확장) |

- **근거:** 그림책을 읽으며 질문하는 대화식 읽기(dialogic reading)는 2~5세 언어 발달 연구가 있는 방법이며, 어린 아이에게는 빈칸 채우기·"이게 뭐야?" 같은 쉬운 질문부터 권한다. 아기돼지 삼형제의 교훈(가벼우면 날아가고 튼튼해야 버틴다)은 원인과 결과 추론이 자리 잡는 4~5세에 맞다.
- **음성 인식:** 어린 아이일수록 발음 인식 정확도가 떨어진다. 3세 이하를 말로 답하게 하는 흐름은 불안정하므로 듣기·고르기 단계에서는 누르기를 주 입력으로 둔다. 실제 아이 음성의 인식률은 미측정이다.
- **단계 정하기:** 보호자가 처음 한 번 아이 나이를 고른다. 대화 단계에서 계속 답하지 못하면 기존 3회 실패 → 보기 카드로 내려가며(§4), 카드를 잘 고르면 다음 질문을 자유 답변으로 올리는 자동 조절을 후속으로 검토한다.
- **제출 범위 제안:** 데모·제출물의 대상은 "4~7세, 기본은 대화 단계"로 명시한다. 고르기 단계(처음부터 카드)는 기존 보기 카드를 재사용할 수 있어 여유가 있으면 넣고, 듣기·만들기 단계와 자동 조절은 제출 후 확장으로 둔다.

## 5. 음성·낭독 기능

### 첫 문장부터 재생·다음 장면 미리 준비·기본 목소리 앱 내장·Modal 음성 서버 — 2026-10-31 저녁 현준님 결정

- **아래 '장면 전체 음성 준비 후 전환'을 대체한다.** 장면 전체를 기다리면 Modal에서도 6줄에 23~27초, Mac에서 67~106초가 걸렸다. 이제 장면의 첫 문장이 준비되면 페이지를 열고, 나머지 문장은 앞 문장을 읽는 동안 순서대로 받는다. 준비 안 된 문장은 최대 6×30초 다시 기다리고, 그래도 안 되면 '목소리 다시 준비하기'를 띄운다(기계 음성으로 바꾸지 않음). `/api/voice/scene`은 독서 화면에서 더 쓰지 않는다.
- **우선순위:** 지금 여는 장면 → 다음에 열릴 수 있는 장면(세 선택지가 여는 정해진 장면, 각 첫 문장 먼저, `POST /api/voice/ahead`) → 동화책 나머지(목소리 저장 직후 첫 장면부터). AI 버전에서 아이가 쓴·말한 답은 AI가 글을 새로 쓰므로 미리 준비할 수 없다.
- **기본 목소리 앱 내장:** 기본 목소리(낭독자 LibriTTS-R 121, 돼지 237·5683·4507, 늑대 1188)와 내장 남성 낭독자(7127)의 정해진 문장·맞장구·선택지를 `prototype/audio/pack/`에 넣어 서버 없이 재생한다. 부모 목소리는 항상 서버에서 만든다. 대본이나 말투 설정이 바뀌면 `python -m narration.pack`으로 바뀐 줄만 다시 만들고, 테스트가 낡은 파일을 잡는다.
- **음성 서버:** 앱은 기본으로 Modal(`deploy/modal_voice.py`, 미국 동부, L4)을 쓴다. 이 Mac의 서버는 `?voiceServer=http://127.0.0.1:8100`. Modal에는 Meta API 키를 두지 않기로 했다(현준님 결정): 목소리 등록은 되지만 동의 문장 자동 확인·구간 받아 적기·연습 문장 기준 음성 만들기는 Modal에서 동작하지 않는다.
- **실측(AI 버전, Modal, 한국어):** 답 후 맞장구 0.8초, AI 글 4.5초, 첫 문장 목소리 10.1초, 그림 도착 24.8초에 페이지 전환. 그림 대기(그림 표시 전 진행 차단)가 가장 길다. 기계 음성 0줄.

### 장면 전체 음성 준비 후 전환·연속 낭독 — 2026-10-31 최신 사용자 요청

- **main 반영 검증:** 영상 제작 스튜디오·움직임/세그먼트 실험을 제외한 구성에서 Python **334/334**, Node **171/171** 통과. 장면 전체 음성 준비·단일 파일 재생·수동 이동·첫 실패 터치 보기를 유지하며 원본 영상 브랜치의 진행 중 파일은 보존했다.
- **우선 목표:** 한 장면의 본문과 질문을 읽는 중에 다음 줄 합성·다운로드를 기다리는 침묵을 없앤다. 여기서 사전 준비는 모델 가중치 학습이 아니라 해당 장면 음성의 합성·파일 준비다. 아래 과거의 '일부 줄부터 재생' 및 '미준비 줄은 기본 음성' 정책은 현재 독서 본문에서 이 항목으로 대체한다.
- **서버:** `POST /api/voice/scene`는 기존 줄별 화자·말투·감정과 음성 캐시를 사용하되 본문·질문 전체가 준비될 때까지 재생 URL을 반환하지 않는다. 준비된 음성을 단일 PCM WAV로 결합하고 줄별 시간 구간을 제공한다. 긴 앞뒤 무음만 정리하고 문장 안의 자연스러운 쉼은 보존한다. 반복 상태 조회가 합성을 재요청하지 않으며 실패한 작업은 명시적 재시도만 허용한다.
- **독서 화면:** 그림 준비와 전체 음성 준비를 병렬로 진행한다. 한 파일을 전부 다운로드하고 재생 가능한 상태가 된 뒤 새 그림·본문·질문을 열고 낭독한다. 읽는 중에는 줄마다 새 파일이나 합성을 요청하지 않는다. 기존 장면은 준비가 끝날 때까지 유지하며 준비 수/전체 수를 표시한다.
- **적용 범위:** 첫 진입, 일반 진행, 언어·목소리 변경, 이전 장면·다시 듣기, 수동 페이지 이동에 같은 음성 준비 조건을 적용한다. 수동 이동은 기존대로 그림을 건너뛸 수 있으나 낭독을 켠 경우 음성 준비는 기다린다. 같은 질문의 첫 실패 터치 보기는 별도 회복 안내이므로 즉시 열고 활성화한다.
- **실패·취소:** 최대 180초 준비 뒤에는 명시적 '목소리 다시 준비하기' 또는 낭독 끄기를 제공한다. 부분 음성을 먼저 읽거나 장면 중간에 줄별 기본 음성으로 바꾸지 않는다. 재시작·화면 이탈·언어/목소리 변경 시 구준비 결과와 늦은 재생을 차단하고 일시정지·다시 듣기를 보존한다. 재생 오류·퇴출된 로컬 음성·손상 파일은 명시적 재준비로 복구한다.
- **완료 기준:** 첫 줄만 준비된 재현에서 조기 재생이 없어야 하고, 전체 합성·다운로드·재생 준비 전 새 장면 표시가 없어야 한다. 재생 중 추가 HTTP 0회, 단일 파일, 본문·질문 시간 구간과 현재 화자 일치, 중지·재생·재시도·삭제·구결과 차단을 확인한다. 최초 음성 합성 시간은 장면 진입 전 준비 구간에 남으며 실제 기기의 오디오 시작 지연이나 자연스러운 문장 쉼까지 0초로 보장하지 않는다.

### 낭독 대기 단축·재생 제어·저장 목소리 바로 선택 — 2026-10-31 사용자 우선 요청

- 증상: 목소리 등록 후 첫 대사를 30초 이상 기다리거나 줄마다 긴 침묵이 생긴다. 준비 여부를 무시한 줄별 음성 다운로드 대기, 현재 장면보다 앞서는 배경 생성, 한국어 요청 전 영어 모델 로딩을 회귀 검증으로 재현했다.

- 서버가 승인한 다음 장면의 낭독을 그림 대기 중 준비하되 재생은 그림 표시 완료 후에만 시작한다. 현재 대사는 배경 생성보다 우선하고 같은 대사의 준비·중복 요청은 하나의 작업을 재사용한다. 맞장구는 실제 낭독 시작을 지연시키지 않으며 언어별 음성 모델은 요청한 언어만 로드한다.
- 그림 근처에 **재생 / 일시정지** 버튼을 두고 현재 위치에서 이어 읽는다. 준비 중 일시정지도 늦은 자동 재생을 막는다. 장면 변경·마이크 입력·목소리 변경·새로 시작은 이전 재생과 일시정지 상태를 취소한다.
- 환경설정을 열면 서버의 저장된 목소리와 기본 목소리를 같은 화면에서 바로 선택한다. 등록·관리 링크는 유지한다. 목록 실패는 안내하고, 삭제된 선택이나 늦은 목록 응답이 현재 선택을 덮어쓰지 않게 한다.
- 완료 기준: 준비되지 않은 음성·응답 없는 서비스의 긴 대기를 재현하고 해소할 것. 준비된 부모 음성 사용, 재생 위치를 유지한 일시정지·이어 듣기, 장면 전환 중 재생 차단, 설정에서 저장 목소리 선택, 모바일·가로 화면 배치를 검증한다. 새 부모 음성을 항상 즉시 합성하거나 추가 학습의 품질 향상을 보장하지 않는다.

### 배역 음성과 부재 가족 목소리 — 2026-10-30 현준님 결정·제안

**결정 (현준님, 음성 담당)**

- **배역은 섞는 방식으로 한다.** 내레이터(`narrator`)는 부모 목소리, 등장인물은 배역에 맞는 목소리로 읽는다. 아기돼지 삼형제에서는 아래 비교 결과에 따라 돼지(`pig1`~`pig3`)는 부모 목소리로 연기하고 늑대(`wolf`)는 기본 캐릭터 목소리를 쓴다. 보호자 설정에 "모든 배역을 내 목소리로" 옵션을 두고, 이때도 음높이만 바꾸지 않고 배역별 표현 강도·속도를 다르게 준다. 화자는 에이전트 대사의 `speakerId`를 그대로 쓴다.
- **데모 시나리오는 "떨어져 있는 아빠"로 한다.** 훈련·파병·해외 근무로 매일 읽어줄 수 없는 아빠가 녹음해 둔 목소리로 아이가 이야기를 듣는다. 페르소나 P1과 맞고, 고인 목소리보다 덜 민감하다.

**배역 목소리 비교 (10/30)**

같은 늑대·돼지 대사를 네 방식으로 생성했다: A 부모 그대로, B 부모 + 음높이만 변경(±4반음), C 부모 + 표현 강도·속도 조절, D 공개 데이터셋 목소리. 스크립트 `experiments/character_voices.py`, 비교 페이지 `voice/characters.html`. 클립 8개 모두 Muse Voice Transcribe로 받아써 대사 누락이 없음을 확인했다. 현준님이 순서를 섞은 상태로 듣고 매긴 점수(1~5, 인물다움 / 자연스러움):

| 방식 | 늑대 | 돼지 | 중앙 음높이 (늑대 / 돼지, 부모 102Hz) |
|---|---|---|---|
| A 부모 그대로 | 1 / 2 | 1 / 2 | 126 / 113 |
| B 부모 + 음높이만 | 1 / 1 | 1 / 1 | 99 / 141 |
| C 부모 + 연기 | 3 / 3 | **4 / 5** | 264 / 113 |
| D 데이터셋 목소리 | **4 / 3** | 2 / 2 | 127 / 244 |

- **결정: 늑대는 데이터셋 목소리(LibriTTS-R 화자 1188), 돼지는 부모 목소리로 연기(C: `exaggeration` 0.8, `cfg_weight` 0.4, 속도 1.1배).** 내레이터와 돼지 삼형제는 부모 목소리가 되고, 위협하는 늑대만 다른 사람 목소리로 구분된다.
- 음높이만 바꾼 B가 두 배역 모두 가장 낮았다. 로드맵의 "단순 음높이 변경만으로 캐릭터 음성 완성으로 보지 않는다"를 실험으로 확인했다.
- 부모 목소리로 연기한 늑대(C)는 중앙 음높이가 264Hz로 올라가 소리치는 쪽으로 나왔다. 부모 목소리로 낮고 굵은 배역을 만드는 설정은 찾지 못했다.
- 한계: 평가자 1명, 배역당 대사 1줄이다. 돼지 셋끼리의 구분과 다른 대사에서의 안정성은 확인하지 않았다.

**보유 음성·영상으로 목소리 등록 (제안, §12의 "보유 음성·영상에서 참조 음성 추출"을 구체화)**

지금 녹음할 수 없는 가족(떨어져 있는 부모, 고인 등)의 목소리를 기존 영상·음성으로 등록한다.

1. 파일 받기: 영상이면 ffmpeg로 오디오만 추출해 모노 WAV로 바꾼다.
2. 구간 고르기: 무음을 잘라내고 한 사람만 말하는 6~15초 구간을 자동 추천하며, 보호자가 화면에서 구간을 직접 조정한다. 여러 사람이 말하는 영상의 자동 화자 분리는 후속으로 둔다.
3. 품질 확인: 길이·잡음·음량을 점검하고 기준 미달이면 다른 구간을 고르게 한다.

### 이미지와 아이 그림

**2026-10-31 사용자 확정 — 객관식은 저장된 오프라인 그림 재사용:** 단계 2의 객관식 선택은 답이 미리 정해져 있으므로 AI 버전에서도 오프라인 버전의 저장 그림을 사용한다. 아래 10/30의 ‘새 답마다 실시간 생성’ 규칙에 대한 명시적 예외다.

- `prototype/img/`·`prototype/img/scenes/`의 기존 Git 추적 이미지와 `media/scene_registry.json`을 공유한다. 재료별 완성·사건 24개와 다음 집의 빈 터·결말 그림이 이미 저장돼 있으므로 새 이미지 생성이나 중복 파일은 필요하지 않다.
- 서버가 검증한 `selection`이 있는 수용 턴에서 진행 후 집·재료·행동에 정확히 일치하는 그림을 즉시 반환한다. 재료 고르기뿐 아니라 예상·이유 보기와 다음 집 이동·결말에도 적용한다. 모델 생성·검수·작업 큐를 기다리지 않고 `ready/source:prepared_choice/generated:false/generationRequested:false`로 구분한다.
- 저장 그림도 다운로드·디코딩·화면 전환이 완료된 뒤에만 새 본문·질문·입력을 연다. 이는 §7의 ‘실시간 생성 실패 시 준비 그림으로 진행하지 않음’과 구분되는 정상 경로다. 파일 로딩 실패 시 같은 저장 그림을 다시 불러오고 유료 생성으로 재시도하지 않는다.
- 자유 입력은 이전 선택의 `selection`을 이어받지 않고 기존 실시간 생성 경로를 유지한다. 선택 턴이어도 낯선 재료 등 정확한 저장 그림이 없으면 다른 재료로 치환하지 않고 기존 생성 경로를 사용한다. 중복 클릭·언어 변경·재시작의 바인딩 검사를 유지한다.
- 완료 기준: 영어·한국어 객관식으로 한 편을 끝까지 진행하며 각 장면의 저장 파일이 존재하고 이미지 모델 호출이 0회여야 한다. AI 독서 화면은 저장 그림 표시 완료 후 진행하며 자유 입력·생성 실패 잠금·이미지 재로딩 경로도 회귀 검증한다.
- **구현·검증(10/31):** 등록 이미지 28개가 모두 Git 추적 중이며 객관식 전체 분기의 19개 자산 키에 누락이 없다. Node 회귀 97개 통과. Python은 기본 환경에서 낭독을 제외한 247개 통과했고, NumPy가 설치된 기존 Anaconda 환경에서 낭독 25개를 별도 통과했다. 격리된 Chrome과 로컬 모형 제공자로 영어·한국어 각각 9턴을 완주해 18회 모두 `prepared_choice`, 이미지 생성 호출 0회를 확인했다. 클릭→디코딩·전환 완료는 로컬 시험에서 464~544ms였으며 실제 기기·실서비스 지연의 보장치는 아니다. 시험 서버와 Chrome은 종료했다.

**2026-10-30 후속 확정 — 새 답마다 실시간 생성(위 객관식 예외 적용):** 사용자 요청으로 `prototype/agent.html`에 로드맵 단계 2의 이미지·마이크 연결을 구현한다. 준비된 24개 장면만 바꾸는 경로에 더해, 실제 AI 모드는 승인된 새 답마다 Muse Image 편집 1회와 별도 Muse Spark 이미지 검수 1회를 수행한다. §4의 이전 ‘유료 실시간 생성 자동 추가 없음’은 이 명시적 후속 요청으로 갱신한다. 영상 생성은 추가하지 않는다.

- `python3 -m vision.server`에서 이야기·이미지·마이크·기존 카메라를 함께 제공한다. `speech.server`도 카메라를 제외한 같은 이미지·마이크 경로를 제공한다. 오프라인 모드에서는 기존 준비 그림을 사용하고 이미지 모델을 호출하지 않는다.
- 미디어 요청은 세션·장면·버전만 받으며, 서버의 승인된 재료·시공·사건·배역으로 편집한다. 새 재료와 터치 선택의 `spec.selection`을 보존하고 실패한 원문·오디오·카메라 프레임을 이미지 프롬프트에 넣지 않는다. 같은 집의 직전 생성 그림을 후속 사건의 참조로 사용한다.
- 생성 결과를 JPEG로 디코딩·크기 제한하고, 독립 검수에서 안전·재료·배역·행동의 네 항목이 모두 참일 때만 제공한다. 세션별 이미지 URL은 세션 존재·만료를 확인하고 다른 세션에서 읽을 수 없게 한다.
- 같은 응답의 중복 요청과 언어만 바뀐 화면은 진행 중·완료된 작업을 재사용한다. 세션 간 생성 그림은 공유하지 않고 자동 유료 재시도도 하지 않는다. 작업·그림·중복 방지는 로컬 서버 메모리에만 보관한다.
- 그림 대기 중에도 다음 질문의 마이크·글·터치 입력을 사용할 수 있다. 첫 실패 즉시 터치 전환은 이미지·낭독 완료를 기다리지 않는다. 새 그림·준비 그림·실패·이전 그림을 한영 캡션으로 구분하며, 실패하면 일치하는 준비 그림 또는 이전 그림으로 계속한다. 재시작·새 답·언어 전환 뒤 늦은 결과는 현재 바인딩을 확인한 뒤에만 적용한다.
- 완료 증거와 실제 API·브라우저·기기 검증 한계는 [시험 가이드](story-agent.md)의 통합 기록에서 관리한다. 실제 아동 음성·iPad 검증과 운영 영속 작업 기록은 별도 후속이다.

| 삼형제가 도망침 | 고정된 사건 클립 | 아이 캐릭터와 연결한 영상 |
| 프롬프트에 따라 집이 바뀜 | 변경 전후 이미지 전환·조립 애니메이션 | 두 이미지나 참조 이미지를 이용한 실제 변환 영상 |
| 기타 역동적 장면 | 동화별 효과가 큰 장면만 선정 | 품질·비용 검증 후 확대 |

기본 전환 효과와 실제 생성 영상은 구분해 표시한다. 처음부터 모든 페이지를 실시간 영상화하지 않고, 짧은 대표 장면으로 품질·지연·비용·무서움 정도를 확인한다. 후보 길이는 2~5초이며 실제 아이 반응으로 조정한다. Muse Image가 영상을 생성한다고 가정하지 않으며, 영상 모델·제공사·권한·운영비는 미정이다.

영상은 반복 재생 여부·건너뛰기·소리 크기·움직임 줄이기를 지원한다. 정해진 사건과 결말을 벗어난 영상, 캐릭터 붕괴·부자연스러운 변형은 사용하지 않는다. 생성 실패 시 검증된 정지 이미지로 돌아간다.

**2026-10-31 사용자 결정 — 장면 전체 영상 대신 그림 위 객체 움직임(WebP), 낭독 동기화, 배경 움직임, 영상은 일부 장면만:**

- **형식:** GIF는 256색·1비트 투명이라 수채화 그림과 객체 경계가 깨지므로 쓰지 않는다. 그림 위 객체는 알파가 있는 WebP, 장면 전체를 대신하는 생성 클립은 MP4로 한다.
- **방식:** 장면마다 영상을 생성하지 않고 표시 중인 그림 위에서 객체를 움직인다(`prototype/story-motion.js`). 서버가 승인한 `mediaPlan.action`(`build`·`blown_away`·`collapsed`·`eaten`·`melted`·`stood`·`move_to_next_house`·`safe_ending`)마다 프리셋이 있어 낯선 재료도 생성 없이 같은 결과 동작을 한다. 그림의 색을 표본으로 써 짚·과자·아이스크림 조각이 그 재료 색으로 날린다. 생성 대기·추가 비용은 없다.
- **SAM 3.1:** `python3 -m media.motion_regions`가 준비 그림 28장에서 늑대·돼지·집 위치를 찾아 `prototype/img/motion/regions.json`과 부드러운 가장자리 WebP 76개(2.5MB)를 만든다. 무너지거나 녹은 집은 조각들을 합쳐 영역으로 쓴다. 집 조각에서는 앞에 선 돼지·늑대 영역을 비워 집이 흔들릴 때 돼지 일부가 함께 움직이지 않게 한다(`--sprites-only`로 SAM 재호출 없이 다시 만든다). 정확한 마스크는 Meta의 `meta-sam-parser`가 필요한데 이번 환경에서 설치하지 않아 박스 기반 소프트 컷아웃을 쓴다. 실시간 생성 그림은 영역 정보가 없어 기본 위치를 쓴다.
- **낭독 동기화:** `Narration.speak`에 실제 소리가 시작될 때 부르는 `onSpeak`를 추가했다(기존 `onLine`은 음성 준비 전에 호출됨). 브라우저가 부모 음성 재생을 받아들인 뒤, 또는 기본 음성이 읽기 시작할 때 줄마다 한 번만 호출된다. 사건을 말하는 줄(늑대·후·불다·녹다 등 한영 단어)에서 동작이 시작되고, 없으면 마지막 본문 줄에서 시작한다. 일시정지하면 동작도 멈추고, 다시 듣기·언어 전환 시 다시 재생한다. 소리 내어 읽기를 끄면 바로 재생한다.
- **배경:** 그림 전체가 16초 주기로 최대 2.5% 천천히 확대·이동하고, 빛 입자와 돼지 숨쉬기가 계속된다. 확대 때문에 꽉 찬 배치에서는 가장자리가 약 1% 가려진다(§7 '그림 전체가 보이도록'과의 차이, 팀 확인 필요).
- **영상 하이브리드:** `scene_registry.json`의 `clips`에 검수한 MP4가 등록된 장면은 클립이 사건을 보여 주고 프리셋은 쉰다. 현재 등록 클립은 0개이며 Runway 생성은 하지 않았다.
- 그림 표시 전 진행 잠금(§7)은 그대로다. 움직임은 그림 표시가 끝난 뒤 시작하며 입력을 막지 않는다. `prefers-reduced-motion`이면 아무 움직임도 추가하지 않는다.
- **검증:** JavaScript 133개(움직임 8개·낭독 동기화 3개 추가), Python 288개 중 기존 환경 실패 2개(librosa 미설치, Windows 포트 오류 문구)를 제외하고 통과. 헤드리스 Edge에서 오프라인 버전으로 1200×800·1366×768·390×844 화면에서 한 편을 끝까지 진행해 모든 프리셋이 해당 그림에서 재생되고 컷아웃이 그림과 정렬됨을 캡처로 확인했고, 한국어 전환 후 재생도 확인했다. 실제 부모 목소리와의 체감 동기화, iPad·Fold 실기기 성능, 실시간 생성 그림 위 기본 위치의 정확도는 미검증이다.

**2026-10-31 사용자 후속 방향 — 부분 애니메이션:** 모든 장면을 GIF/MP4로 바꾸기보다 기존 그림 위의 주요 객체를 WebP 조각으로 움직이고, 낭독의 사건 시점에 맞추며 배경은 약하게 움직이는 방식을 먼저 검증한다. 이는 브라우저 연출이며 생성형 image-to-video 완료로 간주하지 않는다. 실제 출력 품질·낭독 실패 경로·재생 중단을 대표 장면에서 검수하고, 문제 있는 조각은 제외한다. 검토 내용과 검증 명령은 [부분 애니메이션 검토](../../media/MOTION_REVIEW.md)에 기록한다. 검수된 대표 MP4 실험은 별도 POC로 유지한다.

**2026-10-31 실기기 피드백:** 사용자는 낭독·그림·움직임·화면 전환의 싱크가 맞지 않는다고 보고했다. 위 자동 테스트와 화면 표시 확인은 시간·내용의 동기화 완료 근거가 아니다. 현재 구현은 사건 단어를 찾는 추정 큐와 박스 기반 컷아웃을 사용하며, 실제 발화 시작과 움직임 시작 및 장면별 그림 내용을 함께 검수하고 수정해야 한다. 이 항목은 미완료다.

**2026-10-31 싱크 수정 및 남은 검증:** 부모 음성은 오디오 `playing`, 기본 음성은 발화 `onstart`에서 문장별 큐를 전달한다. 결과 그림은 사건 문장이 실제로 시작될 때까지 이전 그림으로 덮어 두고, 일시정지·재개 시 움직임과 등록된 영상도 함께 멈추거나 재개한다. 박스 기반 WebP 조각은 주변 그림이 섞여 기기에서 어긋나므로 독서 화면에서는 제외하고 검토 화면에서만 볼 수 있다. 짚·종이 결과 대사는 실제 그림처럼 지붕 조각이 날아가 집이 안전하지 않게 되는 것으로 고쳤다. Z Fold8 설치형 WebAPK의 오프라인 한국어 짚집 경로에서 앞선 두 과정 문장 동안 이전 그림을 유지하고, 지푸라기가 날아간다는 문장이 시작될 때 결과 그림이 나타나는 것을 CDP 이벤트와 화면 캡처로 확인했다. 같은 기기에서 다시 재생했을 때 사건 큐가 재발화되었고, 일시정지 시 그림과 효과의 CSS 애니메이션 둘 다 `paused`, 재개 시 둘 다 `running`으로 돌아온 것을 확인했다. 이는 기기 전체 동화·영어·부모 목소리·생성 그림·검수된 MP4의 싱크 완료를 뜻하지 않는다. 다음 검증은 대표 재료별 실기기 전 경로, 실제 부모 음성, 영상 등록 후 오디오와 영상의 시간차 측정이다.

**같은 날 메인 통합:** 메인의 장면 전체 음성 사전 준비·이전/다음 페이지 이동과 통합했다. 준비된 장면 음성은 오디오 `playing` 이후 구간별 `timeupdate`에서 문장 큐를 전달한다. 위 Z Fold8 확인은 이 통합 전 오프라인 기본 음성 경로의 결과다. 통합 코드는 Node 184개와 관련 Python 93개 테스트를 통과했다. 통합 코드를 Z Fold8에 다시 띄우자 장면 음성 서버가 없는 현재 PC에서는 `VOICING` 상태로 재시도/낭독 끄기 안내가 표시됨을 확인했다. 이 환경에서 통합 후 실기기 음성 싱크는 검증할 수 없다. 음성을 끄면 진행할 수 있으나 음성 싱크 검증으로 볼 수 없다.

### 다국어

2026-10-28 사용자 요청으로 프로토타입의 첫 추가 언어를 **한국어**로 정했다. 상단의 English·한국어 버튼으로 안내·동화·질문·선택지를 전환하고 선택한 언어를 기억한다. 시험 화면의 언어 변경은 선택한 재료·사건·진행·실패 횟수를 보존한다. 이미 생성한 현재 대사의 언어를 바꿀 때는 준비된 해당 언어 대사로 표시하고 실제 AI 재생성으로 기록하지 않는다. 이후 새 응답은 선택한 언어로 생성·검증한다. 과거 시험 기록과 직접 입력한 답변은 원문으로 보관한다.

기존 그림책도 같은 언어 설정을 사용하며 한국어에서는 영어 사전 생성 음성을 재생하지 않고 브라우저 한국어 낭독을 사용한다. 이는 부모 목소리 한국어 품질 검증이나 전체 다국어 통합 완료를 뜻하지 않는다.

- [ ] UI, 이야기, 인식 언어, TTS 언어, 가드레일·재시도 문구를 별도로 관리한다. 사용자에게는 읽을 언어와 목소리의 조합으로 제공한다.
- [ ] 이야기 데이터에 언어별 대사를 두고 아이 발화 언어가 달라도 선택 의미를 공통 상태로 정규화한다.
- [ ] 언어별 발음·말투·음성 유사도·교훈 전달·금지 입력·혼합 언어를 검증한다. 현재 영어 TTS 실험이 다른 언어의 품질까지 검증한 것은 아니다.
- [ ] 사용할 Chatterbox 버전·가중치·지원 언어를 고정하고 평가한다. 프로토타입 첫 추가 언어는 한국어로 정했으며, 부모 목소리의 해당 언어 품질은 별도로 검증한다.
  - 10/30 시험(`experiments/korean_narration.py`, 듣기 `voice/korean.html`): chatterbox-tts 0.1.7의 Multilingual 모델이 한국어를 지원한다. 현준님 **영어** 녹음을 기준으로 그림책 한국어 5줄을 만들고 Muse Voice Transcribe로 되받아쓴 글자 오류율은 cfg 0.5 평균 19%, cfg 0(억양 줄이기) 26%. 첫 줄은 0%였지만 "돼지→되지/대지", "무엇으로→워스로"처럼 발음이 흔들렸다(받아쓰기 오류 포함). 한 줄 4~10초. 다음 시험: 한국어로 녹음한 기준 음성. 지금은 한국어 낭독을 기기 음성으로 유지한다.
  - 10/30 추가 시험(같은 5줄, `voice/korean.html`에서 모두 비교): **한국어 기준 음성**(Zeroth-Korean, CC BY 4.0) 화자 B 10%, 화자 A 22%(말 반복 발생). **음성 변환**(맥 Yuna 한국어 TTS → Chatterbox VC로 부모 음색) 36%로 가장 나쁨. 참고로 변환 전 Yuna 자체도 13%여서 받아쓰기 오류가 약 10% 이상 섞인 지표다. 결론(제안): 숫자로는 Multilingual 모델 + **한국어로 말한 기준 음성**이 가장 낫다.
  - **10/30 결정 (현준님, 직접 듣고):** 부모의 **영어** 녹음으로 만든 한국어(cfg 0.5)가 가장 좋게 들린다. 부모는 영어로 한 번만 녹음하고, 같은 목소리로 영어와 한국어를 모두 읽는다. 구현: 낭독 서버 `language: "ko"` → Chatterbox Multilingual, 한국어 그림책·맞장구 미리 생성, 그림책·에이전트·live 화면 모두 한국어도 부모 목소리. 한계: Mac에서 한국어 한 줄 6~9초로 재생보다 느려 실시간 대사 사이에 쉼이 생긴다(에이전트 한국어 실측: 답→대사 11.5초, 첫 낭독 21.7초, 줄 사이 6~8초). 클라우드 GPU 또는 다른 방법으로 줄여야 한다. 부모 목소리 한국어 낭독에는 부모의 한국어 녹음이 필요하고, 기본 한국어 목소리는 화자 B 같은 공개 한국어 화자로 기기 음성을 대체할 수 있다. 팀원들이 한국어로 시험 중이라 우선순위가 높다.

2. **엄마 목소리로 한국어:** 엄마가 모국어나 편한 말로 녹음한 목소리를 기준으로, 그림책은 표준 한국어 발음으로 읽는다(언어를 넘는 목소리 복제). 정서적 연결(엄마 목소리)과 한국어 입력을 함께 준다. 10/30 시험에서 영어 기준 음성으로 만든 한국어는 글자 오류율 19%로 아직 부족하다(위 시험). 베트남어·중국어 기준 음성에서 억양이 얼마나 옮는지 검증이 먼저다.
3. **부모 언어 지키기 (기존 페르소나 P2):** 같은 장면을 부모 언어로도 읽어 준다. Chatterbox Multilingual 23개 언어에는 중국어·일본어·러시아어가 있지만 **베트남어·필리핀어(타갈로그어)·크메르어·태국어는 없다.** 베트남어 등은 다른 음성 합성 모델이 필요하다(목소리 복제 없는 기본 음성 후보 포함, 라이선스 확인 필요).

- [ ] 공개 데이터(예: Common Voice, CC0)의 베트남어·중국어 화자 음성을 기준으로 한국어 그림책을 만들고, 받아쓰기 오류율과 직접 듣기로 억양 전이를 확인한다.
- [ ] 한국어 그림책 낭독을 기기 음성 대신 자연스러운 기본 한국어 목소리(공개 데이터·라이선스 확인)로 바꿀지 검토한다.

### 화면 비율 변경 시 독서 UI 유지 — 2026-10-31 사용자 요청

- 화면 비율을 바꾸면 창이 닫힌 것처럼 보이는 문제를 수정한다. 휴대폰 세로·가로, 태블릿, 분할 창, 넓은 모니터에서 그림·본문·질문·입력·선택지가 계속 접근 가능해야 한다. 창 크기 변경만으로 이야기를 재시작하거나 입력한 답을 지우지 않는다.
- 원인은 이전 데모의 가로 배치가 새 독서 화면에 적용되며 `align-self:center`와 `container-type:inline-size`가 그림책 폭을 축소한 것이다. Chrome `844×390`에서 폭 **2px**로 재현했고, 독서 화면 전용 스타일과 명시적 폭·정렬로 수정 후 **810px**를 확인했다.
- 좁은 세로 화면은 그림 위·본문 아래로 배치한다. 충분히 넓은 가로 화면은 그림 왼쪽·본문 오른쪽으로 전환한다. 그림은 전체가 보이도록 맞추고 본문 크기와 버튼의 터치 영역을 유지한다. 높이가 부족하거나 키보드가 올라온 크기에서는 문서 스크롤로 모든 조작에 접근한다. 설정·대사·카메라를 각각 고정 높이로 잘라 숨기지 않는다.
- 언어·버전·설정과 답 입력 버튼은 사용 가능한 폭에 맞춰 배치하며 마이크는 조작 영역 오른쪽에 유지한다. 일반 조작은 44px 이상, 객관식은 기본 독서 화면 80px 이상·진단 화면 72px 이상을 유지한다. 개발용 `agent.html`도 좁은 폭의 버튼 넘침을 보완하되 앱 안에 진단 화면 링크를 추가하지 않는다.
- Chrome에서 13개 뷰포트의 표지·본문·객관식·설정·입력 유지와 진단 화면 4개 폭을 확인했다. JavaScript 회귀 테스트 78개 통과. 검사 수치·재현 절차·실기기 한계는 [검증 기록](responsive-ui-2026-10-31.md)에 둔다. Safari·실제 모바일 키보드·폴드 힌지는 별도 실기기 검증 대상이다.

2026-10-29 기기 기준: 사용자는 Z Fold8을 우선 개발·검증 기기로 예상한다. 접은 화면·펼친 화면·회전·화면 전환 중 상태 유지를 검증 대상으로 둔다. 실제 기기 검증은 미실행이며 iPad 배포 목표를 변경한 것으로 확정하지 않는다.

2026-10-29 UI 일관성 수정: 독서 화면의 마이크는 화면 크기·방향에 관계없이 본문 아래 조작 영역 오른쪽에 둔다. 상태 안내와 다시 말하기는 왼쪽에 유지하며, 반응형 전환으로 좌우를 바꾸지 않는다. 그림·본문의 세로/두 페이지 배치와 마이크 크기는 기기에 맞게 조절한다.

| 영역 | 포함 기능 | 동작 기준 |
| --- | --- | --- |
| 시작 화면 | 동화 목록·표지·이어 읽기 | 어려운 설정을 초기 화면에 나열하지 않음 |
| 아이 독서 화면 | 그림/영상, 낭독, 마이크, 단순한 페이지 이동 | 큰 터치 영역, 읽지 못해도 알 수 있는 아이콘·음성 안내 |
| 독서 조작 | 처음부터, 이전·다음, 일시정지·재개, 다시 듣기 | 필수 질문이 남은 페이지는 다음 이동 전에 응답·안전한 기본 선택을 안내 |
| 재시도 | 첫 실패 즉시 세 키워드 터치 선택 전용으로 전환 | 같은 질문의 음성·글·카메라를 잠그고, 낭독·추가 발화를 기다리지 않고 선택 |
| 보호자 설정 | 낭독 속도, 엄마·아빠·기본 음성, 배역 음성, 언어, 캐릭터·아이 그림 | 보호자 확인을 거친 영역에서 관리, 가족 설정 저장 |
| 프로필·개인정보 | 가족 프로필, 녹음 동의, 등록 음성·그림·독서 기록 삭제 | 아이 정보는 기능에 필요한 최소 범위로 수집 |
| 운영자 도구 | 동화·장면 버전, 생성 작업 상태·오류·비용 | 가족 설정과 분리된 권한, 다른 가족 음성·그림은 노출하지 않음 |

사용자가 말한 관리자 페이지는 우선 **보호자 설정**으로 구현한다. 서비스 운영자용 도구는 필요한 운영 기능만 추가한다.

- 이전 페이지로 돌아가면 당시의 그림·대사·선택을 재생하고 API를 다시 호출하지 않는다.
- 과거 질문에 새 답을 하면 그 이후 기록을 새 분기로 만들고, 이전 분기의 생성 작업이 현재 화면을 덮어쓰지 않게 한다.
- 재시작·페이지 이동·음성 변경 때 재생 중인 소리와 사용하지 않을 작업을 취소하거나 결과 적용을 차단한다.
- 앱 종료·전화·화면 잠금·오디오 경로 변경 후 돌아오면 안전한 위치에서 이어 읽는다.

## 8. 추가로 필요한 기반 기능

- [ ] **서버와 작업 관리:** API 키를 클라이언트에 포함하지 않기, 세션별 권한, 업로드 크기 제한, 녹음 변환, 이미지·TTS·영상 비동기 작업과 진행 상태.
- [ ] **저장과 복원:** 장면·선택·대사·미디어 버전·음성·언어를 저장하고 중단 후 복구. 초기에는 복잡한 계정 없이 제한된 세션으로 검증하되 가족 데이터의 접근 경계는 유지.
- [ ] **비용과 속도:** 답·이미지·언어·목소리·모델 버전에 따른 캐시, 가족 음성 캐시의 가족별 분리, 제한된 사전 생성, 중복 요청 방지, 재시도 횟수·세션 예산 상한.
- [ ] **오류와 대체 경험:** 무음·권한 거절·망 단절·모델 거절·속도 제한·타임아웃에 각각 복구 경로. 생성 실패 시 기존 페이지와 검증된 대사로 진행.
- [ ] **기록과 진단:** 모델·장면·작업 식별자, 처리 시간·오류·비용을 기록. 원본 아이 음성·사진·전체 발화는 기본 진단 로그에 남기지 않기. 실제 측정 후 목표 지연·비용 확정.
- [ ] **개인정보와 동의:** 부모 음성·아이 녹음·그림의 수집 목적·저장 기간·외부 전송을 설명. 가족별 접근 통제, 임시 링크, 삭제 기능. 음성 삭제는 참조 녹음·파생 음성·캐시와 재생 링크를 함께 처리하고 백업 보관 방식도 명시.
- [ ] **iPad 배포 준비:** 마이크·카메라 권한 설명, 서명과 앱 식별자, 실제 기기 테스트, 개인정보 설명·지원 연락처·스토어 자료. 어린이 대상 분류와 외부 AI로 보내는 음성·그림의 데이터 흐름을 공개 배포 전에 검토. 보호자 동의 화면만으로 심사 요건 충족을 가정하지 않기.
- [ ] **접근성:** 큰 글씨·터치 영역, 자막, 색상에만 의존하지 않는 안내, 움직임 줄이기, 읽기 속도·음량 조절.

자연스러운 낭독과 아이 친화성은 보호자 동의하의 사용자 관찰로 검증한다. 질문 이해, 기다리는 시간, 재시도 성공, 음성 자연스러움, 영상의 무서움·산만함을 기록한다. 테스트 표본과 실패 사례를 남기고 “절대 안전”이나 “항상 일관됨”을 주장하지 않는다.

## 10. 바로 착수할 순서

1. **첫 편의 장면 명세 작성:** 고정 사건·결말·변경 항목·예상 답·자연스러운 거절·기본 대체 장면을 정의한다. 동시에 대상 연령·언어·iPad 검증 기기를 정한다.
2. **작은 서버와 상태 저장 구축:** 키 보호, 세션·장면·작업 식별자, 제한된 생성 요청, 기본 오류 처리를 넣는다.
3. **개발용 텍스트로 가드레일 검증:** 실제 마이크를 붙이기 전 정상·위험·불가능·결말 변경 요청을 확인한다.
4. **마이크 → Voice 연결:** 녹음·변환·인식 결과 확인·재녹음을 브라우저와 iPad에서 검증한다.
5. **Spark → Image 연결:** 입력에 따라 실제 그림·대사가 바뀌고 끝까지 완주하도록 한다. 생성·재시작·페이지 이동의 충돌을 확인한다.
6. **부모 음성 적용:** 동의·등록·미리 듣기·기본 배역 음성·삭제와 함께 첫 편에 연결한다.
7. **독서 UI 안정화 후 콘텐츠 확대:** 보호자 설정과 저장·재개를 다듬고, 공통 형식으로 동화 두 편을 추가한다.
8. **확장과 배포:** 아이 그림 → 대표 영상 → 추가 언어를 검증하면서 iPad 베타를 준비한다. 데모 대본은 초기에 쓰고 실제 녹화는 동작이 안정된 시점에 한다.

## 11. 확인 자료

아래 외부 자료는 2026-10-27 확인했다. 구현 시 사용할 버전과 배포 조건을 다시 대조한다.

- [Meta Model API 개요](https://dev.meta.ai/docs/overview): 모델별 입력·출력·인증. Muse Voice는 인식이며 TTS는 별도다.
- [Muse Voice 가이드](https://dev.meta.ai/docs/speech-to-text): WAV 입력·모드·응답, 단어별 타임스탬프·신뢰도 점수 미제공.
- [Muse Image 가이드](https://dev.meta.ai/docs/image-generation): 이미지 생성·편집·참조 이미지 활용.

### 회의에서 정한 우선순위

- **실시간 동화 진행 에이전트 우선:** 아이 답이 허용 가능한지 판단하고 정해진 이야기로 유도한다. 원문 동화를 자동 분석해 등장인물·장면·질문을 구성하는 별도 에이전트는 후순위(TBD)다. 초기에는 사람이 장면과 배역 메타데이터를 작성한다.
- **부모 목소리를 핵심 경험에 포함:** 기존 직접 녹음·복제·배역 음성을 우선 연결한다. 보유 음성·영상에서 참조 음성을 추출하는 입력 방식은 제안으로 추가하며, 이용 권한·동의·품질을 확인한 뒤 범위를 정한다.
- **첫 편의 가변 범위를 제한:** 집 재료 등 허용 항목을 바꾸고 등장인물·주요 사건·결말은 유지한다. 재료에 따른 인과관계는 검증한다. 아이 그림·캐릭터 개인화는 이후 확장 백로그에 유지한다.
- **image to video를 개발 대상으로 채택:** 늑대의 바람·집의 변화 같은 대표 장면부터 검증한다. 회의의 10초 이내 예시와 기존 2~5초 후보 중 최종 길이, 모델·제공사·비용·지연은 미정이다.
- **넓은 화면 기기 검토:** iPad 목표와 사전 검증을 유지하면서 Android 태블릿·폴더블도 후보로 검토한다. 플랫폼 변경이나 구현 기술은 확정하지 않았다.

### 2026-10-29 img2vid 1~2단계 구현

`media/contracts.py`의 MediaSpec 검사, action별 `scene_registry.json` 자산 선택, `media/jobs.py`의 비동기 로컬 작업·중복 방지·제한시간·취소·구버전 차단을 구현했다. 언어만 변경하면 진행 중 또는 완료된 공개 로컬 콘텐츠를 재사용한다. 기존 동화 서버 파일은 수정하지 않고 `python -m media.server` 확장 서버로 현재 서버 세션에서만 작업을 생성·조회·취소한다. UI 플레이어는 별도 ui_mvp 범위이며 아직 연결되지 않았다. 검수된 영상은 레지스트리가 비어 있어 현재 기본 실행은 정지 이미지 fallback이다. 키·외부 생성 호출·유료 제출 영속 기록·실제 영상 생성·Fold8 재생 검증은 미실행이다. 실제 실행/API/한도/후속 연결은 [미디어 API](../../media/API.md)를 따른다.


### 2026-10-29 미디어 취소 후 새 요청 복구 보강

취소된 콘텐츠가 새 세션·언어 변경 후 새 version에도 재사용돼 `cancelled/apply=false/image=null`로 남던 오류를 회귀 테스트로 재현하고 수정했다. 같은 요청의 취소·중복 방지 기록은 유지하되 새 요청은 취소된 콘텐츠 작업을 대체한다. 각 바인딩·제공자 실행·타이머가 정확한 작업 인스턴스를 참조하도록 분리해 이전 완료·제한시간 콜백·반복 취소가 새 작업을 변경하지 못하게 했다. 새 세션·새 version·늦은 완료/타이머·HTTP 통합 경로의 회귀 테스트를 추가했다. 외부 영상 생성과 UI 플레이어 범위는 변경하지 않는다.

### 2026-10-31 live.html 장면 단위 동기화와 고정 레이아웃 — 사용자 후속 요구

- `prototype/live.html`의 한 장면은 서버의 `sessionId`·`sceneId`·`version`에 묶인 그림, 본문, 질문/터치 보기, 낭독을 한 묶음으로 취급한다. 이전 장면의 늦은 이미지·음성은 새 장면에 적용하지 않는다.

- 5→6 장면에서 독립 맞장구("Let's turn the page", "Ready? Here we go")와 다음 장면 낭독이 겹친 사용자 관찰을 반영해 `live.html`의 독립 맞장구 재생·예열을 제거한다. 장면의 본문과 질문 낭독이 끝나기 전에는 답변·마이크를 활성화하지 않고, 음성 중단 시에는 이전 장면 재생 완료 대기를 즉시 해제한다.
- 녹음·인식·터치 보기 상태 변화는 입력칸, 마이크, 상태 문구와 보기의 고정 영역 안에서 처리해 카드 크기와 칸 배치를 움직이지 않는다. 음성 인식 실패나 마이크 오류는 첫 실패 즉시 그 장면의 검증된 터치 보기를 보여 준다.

### 범위 결정 (제안)

1. **아이 답이 바꾸는 범위는 재료와 미리 설계한 사건으로 한정한다.** 2차 회의 결정을 유지한다. "비행기를 만들어 날아간다" 같은 행동 변경은 제출 후 확장으로 두고 데모에서는 다음 단계로만 소개한다. 프롬프트·속도 최적화가 쉬워지고 3분 데모에 필요한 한 경로의 완성도에 집중할 수 있다.
2. **확정된 선택은 이후 장면에 계속 남는다.** 재료가 정해지면 다음 그림(늑대 장면 등)·대사·결말 요약이 서버 상태의 같은 값을 쓴다. 미디어는 클라이언트 값이 아니라 서버 snapshot을 기준으로 다음 장면을 만든다(현재 `media/contracts.py` 방식 유지).
3. **데모 경로를 미리 정하고 그 그림은 질문 시점에 미리 생성한다.** 영어로, 예상 답 1개, 엉뚱한 답 1개(아이스크림 또는 과자), 첫 실패 즉시 터치 카드 전환 1회를 포함한다. 예상 밖 답의 실시간 생성은 한 번만 보여준다. 기다리는 구간을 줄여 편집하면 영상에 표시한다.
4. **생성형 영상은 Runway 키가 11/1까지 없으면 제출판에서 뺀다.** Runway는 Meta 모델이 아니어서 Meta 모델 활용 평가에 기여하지 않는다. Best Creative Build는 Muse Image의 기여를 보므로, 실제 Muse Image 편집(P0-2)이 영상보다 우선이다.
5. **음성 서버는 Modal 승인 전까지 현준님 Mac에서 Chatterbox를 실행한다.** 외부 호스팅은 심사용 공개 데모가 필요할 때만 검토한다.
6. **영어 실모델 완주를 통합 검증에 넣는다.** 데모와 산출물은 영어인데(`plan.md` 결정), 실제 모델 완주 기록은 한국어뿐이다.

### 데모 영상과 제출 (형서 주도)

- **콘티 초안 11/1까지.** [06 문서의 구성안](../hackathon_introduce/06_제출준비와_데모.md)을 따른다. 문제(바쁜 부모, 보기만 하는 아이) → 실제 화면 녹화(말하기 → 판정 → 그림 변화 → 부모 목소리) → 엉뚱한 답과 첫 실패 즉시 터치 카드 → Meta 모델의 역할(Voice Transcribe, Spark, Image) → 마무리.
- **핵심 기능은 실제 화면 녹화로 보여준다.** 도입부 생활 장면은 AI 생성 이미지·영상을 쓸 수 있다. 출연 방식(팀원 출연 또는 전부 AI)은 아직 정하지 않았다.
- **아이 목소리 녹음이 없다.** 성인이 말하거나 합성 음성을 쓰면 영상에서 그렇다고 밝힌다.
- **제출 점검:** 공개 저장소에 키·비공개 자료가 없는지 확인, 팀원 4명 명단, Best Creative Build 지원 표시, 제출 폼 필드 사전 확인, 해커톤 기간에 새로 만든 부분과 이전 작업 구분.

### 위험

- **금요일에 P0 1~4가 붙지 않으면** 데모가 고정 그림책과 텍스트 에이전트 두 화면으로 갈린다. 이때는 데모 경로만 사전 생성 그림·음성으로 한 화면에 잇고, 실시간 생성은 별도 장면으로 보여준다.
- **대기 시간:** 에이전트 15~30초와 그림 12~20초가 순서대로 이어지면 한 턴이 30초를 넘을 수 있다. 서로 다른 실험의 수치이므로 통합 후 다시 잰다.
- **모델 표현 한계:** "비닐"을 못 알아들음, "시멘트"를 "모르타르"로 바꿈, 아이의 예측에 공감만 하고 결론으로 넘어감(지호님 관찰, 한국어).
- **공동 작업 시간 부족:** 금요일 밤 이후 넷이 함께 일할 시간이 없다. 통합 결과와 막힌 점은 카톡에 바로 공유한다.
