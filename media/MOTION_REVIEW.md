# 장면 부분 애니메이션 검토 (2026-10-31)

## 결정과 구분

사용자가 요청한 방향은 모든 페이지를 GIF/MP4로 바꾸는 대신, 기존 그림 위의 필요한 객체만 움직이고 낭독과 사건을 맞추며 배경에 약한 움직임을 주는 것이다. 현재 `prototype/story-motion.js`는 **정적 WebP 조각 + 브라우저 애니메이션**으로 이를 시도한다. 움직이는 WebP 파일이나 생성형 image-to-video 결과물은 아니다. 실제 영상 POC의 완료 기준은 `IMG2VID_POC.md`를 따른다.

첫 제출에서는 검수된 그림과 낭독으로 한 편을 완주하는 흐름을 먼저 지키고, 부분 애니메이션은 대표 장면에서 품질을 확인한 뒤 노출한다. 영상 제공사 키가 없더라도 이 경로를 시험할 수 있다.

## 코드·자산 검토

- 좋은 점: `mediaPlan.action`에 따른 정해진 연출, 낭독 시작 콜백, 일시정지·장면 이동 시 정리, 움직임 줄이기 설정, 검수된 MP4 우선 경로가 있다. 새 답을 받아 임의 사건을 만들지 않는다.
- **화질 보류:** `media/motion_regions.py`는 SAM 3.1의 상자 좌표를 사용하지만 실제 객체 마스크를 쓰지 않는다. 둥글게 흐린 사각형 안에 원래 배경과 이웃 객체가 남는다. 예를 들어 `wolf_straw.house.webp`에는 왼쪽 돼지의 일부가 들어 있어 집을 흔들면 그 부분도 같이 움직일 수 있다. `wolf_straw.wolf.webp`에도 주변 울타리·배경이 들어 있다. 파일 무결성 검사는 이를 발견하지 못하므로 실제 재생을 눈으로 확인해야 한다.
- **동기화 보류:** `narration.js`의 `onSpeak`는 부모 음성 `clip.play()`의 Promise가 성공하기 전에 호출된다. 브라우저가 재생을 거절하면 효과가 먼저 시작되고 대체 음성은 뒤에 나온다. 낭독 콜백의 의미와 실패 경로를 브라우저에서 확인해야 한다.
- **장면 표현 보류:** 이미 무너진 집 그림에서 `collapsed` 연출을 다시 실행할 때 현재 그림과 움직임이 같은 사건을 보여 주는지 확인해야 한다. 같은 객체가 원본 그림과 WebP 조각에 중복돼 흔들림이나 점프처럼 보일 수도 있다.

## 검수 순서

1. `python -m media.validate_motion_assets`로 모든 등록 그림의 영역·파일·디코딩·크기·투명도·누락을 검사한다. 이 검사는 화면 품질을 보증하지 않는다.
2. 서버 실행 후 `/prototype/motion-review.html`에서 대표 장면 `wolf_straw.jpg`, `scenes/house1_wood_collapsed.jpg`, `scenes/house1_icecream_melted.jpg`, `scenes/house3_stone_stood.jpg`의 원본·정지 조각·움직임을 비교한다. 경계선과 이웃 객체 중복을 빠르게 찾는 용도다.
3. 통과 후보를 실제 독서 화면에서 재생한다. 집 위치, 바람 방향, 낭독 시점, 영상 재생과의 중복을 기록한다.
4. 경계선이 보이는 조각은 해당 장면에서 움직임을 끄거나 실제 마스크/수동 검수 컷아웃으로 교체한다. 대표 장면에서 통과한 연출만 데모에 쓴다.
5. 재생 거절·일시정지·녹음 시작·페이지 이동·언어 변경·움직임 줄이기를 확인한다. 실제 기기와 실제 음성으로 확인하기 전에는 완료로 표시하지 않는다.

## 검증 기록

2026-10-31 현재 작업 중인 세션의 코드를 기준으로 관련 Node 테스트 28개와 전체 Node 테스트 132개, `tests.test_server` Python 테스트 23개가 통과했다(`STORYSHAPER_TEST_PYTHON=python` 사용). 자산 검사는 작업 도중 집 영역 누락과 빈 WebP를 발견했고, 생성 재시도 뒤 28개 그림·76개 조각에서 통과했다. Claude 세션이 자산을 계속 작성 중이므로 최종 자산 전체에 대한 재검사가 필요하다. 실제 브라우저 화면과 기기 재생은 아직 확인하지 않았다.

2026-10-31 Z Fold8 연결 점검: Windows `pnputil`에서 Samsung MTP와 ADB Interface가 모두 `Started`로 확인됐다. 오프라인 미디어 서버의 검수 HTML·JS·manifest·WebP·독서 HTML이 모두 HTTP 200 및 올바른 MIME으로 응답했다. 이 PC에 ADB 실행 파일이 없어 기기 인증·브라우저 재생은 아직 확인하지 못했다. Google 공식 SDK Platform-Tools는 사용 전 라이선스 동의가 필요해 사용자 답변을 기다린다.

**2026-10-31 Z Fold8 실제 화면 후속 검증:** Google Platform-Tools를 임시 폴더에 준비하고 사용자가 USB 디버깅을 허용한 뒤 ADB에서 `SM_F971N`을 `device`로 확인했다. `adb reverse tcp:8000 tcp:8000`으로 PC의 오프라인 미디어 서버에 연결했다. 휴대폰 Chrome의 `/prototype/motion-review.html`에서 `wolf_straw.jpg`의 `blown_away`를 실행하니 WebP 조각 3개, canvas 1개, 실행 중인 애니메이션 5개가 확인됐고 0.45초 간격의 기기 렌더링 프레임이 달랐다. 이어 실제 `/prototype/live.html`의 오프라인 동화에서 첫 답 `짚`, 다음 답 `날아가요`를 선택해 늑대 장면에 도달했다. 해당 장면은 조각 3개와 실행 중인 애니메이션 6개를 표시했고 0.4초 간격의 기기 프레임에서 266,090픽셀이 달랐다(12/255보다 큰 채널 차 기준). 화면 캡처에서도 바람 선과 집 주변 움직임이 보였다. 시험 당시 Chrome CSS 뷰포트는 932×553, DPR 2.625였고 낭독을 잠시 껐다가 원래 설정으로 복구했다. **확인 범위는 펼친 가로 화면의 오프라인 경로에서 실제 움직임 표시까지**다. 부모 음성 동기화·마이크·세로 화면·장시간 성능·객체 경계의 데모 품질은 별도로 검수해야 한다. 재현 도구는 `tests/device-motion-smoke.cjs`, `tests/device-reader-motion-smoke.cjs`다.
